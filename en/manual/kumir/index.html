01 · overview

What is Kumir

Kumir is a computer science and programming teaching suite designed for primary and secondary school students. Its school algorithmic language uses Russian words and an explicit format for declaring data, starting and ending algorithms, and controlling execution.

The suite includes virtual performers that support interactive tasks. Language and environment work together pedagogically: exercises can combine calculations with actions by a performer such as a Robot or a Drafter.

Status in Potoo IDE: Kumir is under evaluation. This page describes the source system and does not promise that Kumir files or performers work in the app.

02 · school context

Goals and organization

The Kumir project was designed to support school computer science curricula and algorithmic thinking. The language resembles a structured algorithmic notation: declarations and statements appear in recognizable blocks, using terms from the students’ language.

The system brings together:

  • an editor for writing algorithms;
  • program execution and diagnostics;
  • school material and exercises;
  • performers that model environments or tasks.

Exact features change between the 1.x and 2.x families and their distributions. Consult the documentation included with the installed version.

03 · program structure

The shape of an algorithm

A school algorithm can have a heading, declarations, an executable section, and an ending. The example below illustrates Russian vocabulary commonly associated with Kumir’s algorithmic language; confirm the complete form in the manual for your version:

алг квадрат
нач
  цел n, результат
  ввод n
  результат := n * n
  вывод результат
кон

алг introduces the algorithm, нач starts its body, and кон ends it. ввод and вывод handle input and output; := assigns an expression result. Type names and declaration placement should follow version-specific documentation.

Read the program frame in layers

Header and body words help identify where each responsibility begins. In the earlier example, алг names the algorithm; the declaration gives the data type; нач starts the instructions; and кон closes the body. Input and output calls sit beside the operations that depend on them.

Documented formRole in the example
алгIdentifies the algorithm being described.
нач / конMark the beginning and end of the body.
вводReads a value into the named variable.
выводDisplays a value or expression.
:=Stores an expression result in a variable.

When reading an algorithm, find the input before interpreting the calculation, then follow the instructions in order to the output. Do not confuse assignment with comparison: the symbol shown for storing a result differs from the equality test used in a condition.

04 · data and expressions

Types and values

The algorithmic language presents types such as integers and real values, along with text and logical data depending on the version. Reserved words are written in Cyrillic.

FormUse
целDeclares integer values in school materials.
вещDeclares real values in school materials.
вводReceives values.
выводDisplays values or text.
:=Stores the value of an expression.

Arithmetic operators and relations form expressions used in calculations and conditions. Check the materials for the version to confirm how strings, characters, logical values, and collections are declared; do not generalize names and rules from a different implementation.

Choose a type for the task

A declaration makes explicit what kind of value a variable should hold. Integers suit counters, quantities, and positions; real values represent measurements that can include a fraction; logical values express test results. Language materials also distinguish characters and text, with rules that depend on the version.

Before choosing a type, ask whether the problem permits fractions, what range of values is expected, and whether the value will be used in a condition or an index. Keep operands compatible and consult the documentation for conversions and division. A construct accepted by the editor does not guarantee that its result makes sense for the task.

When a structure stores several values, check the collection type, its dimensions, and how each position is accessed. Do not assume that indices begin at zero or one; follow the task and the example from the installed version.

05 · control flow

Conditions and loops

Kumir provides constructs for decisions, counted loops, and conditional loops. Its notation uses opening and closing words, helping beginners identify the boundary of each block.

  • Decision: select a branch based on a condition.
  • Conditional loop: repeat instructions while a condition is true.
  • Counted loop: traverse a defined range or quantity.
  • Subprograms: organize a solution into helper algorithms, depending on the version.

Official material provides each construct’s exact form. Check the block ending and what happens when a limit is reached.

Recognize block boundaries

Kumir materials use Russian words for selection and repetition. Technical documentation lists если, то, иначе, and все for conditional structures, as well as loop vocabulary such as пока, нц, кц, для, от, до, and шаг. The closing word and the position of the block start depend on the construct and version; check a complete example before typing a block from memory.

To review a condition, write in plain language what each branch means. To review a loop, record:

  • the counter's initial value, when there is one;
  • the condition that permits another iteration;
  • the step or update that changes state;
  • the expected state when execution ends.

If the control variable never approaches the stopping condition, the algorithm may not terminate. If a boundary is included or excluded, test a small case in the environment before generalizing.

06 · virtual performers

Robot, Drafter, and tasks

A notable feature of the system is its use of virtual performers in activities. The Robot can be programmed to traverse a scenario; the Drafter (Чертёжник) can draw figures using movement commands. They make an algorithm’s outcome visible and provide a context for decomposing paths into actions.

For a performer task, read the initial conditions, available commands, and goal. Then:

  1. split the route into simple segments or shapes;
  2. identify repeated movements;
  3. use decisions when the scenario requires a response;
  4. run the program and compare the final world with the goal.

Commands differ by performer and distribution; there is no single set shared by every Kumir task.

Commands, questions, and performer state

A virtual performer is a model with its own state and accepted commands. For a Robot task, state may include the cell, direction, and field walls; a movement command changes that state, while a question checks a property of the surroundings. The Drafter works with a graphics task and drawing movements.

Before writing a route, turn the prompt into initial conditions and a goal. Then divide the goal into observable steps: reach a cell, go around an obstacle, or finish a figure. Use only commands listed for the performer in that version; names from another world are not interchangeable.

Step-by-step execution helps reveal the effect of each action. If the performer leaves the expected scenario, compare position and direction after each command instead of changing several parts at once.

07 · worked example

Double a sequence of values

A program that reads values and transforms them can be developed in three parts: input, calculation, and output. For each new item, calculate twice its value and display the result. The loop ends when the exercise’s rule says no further inputs remain.

  1. Declare the input value and calculated value.
  2. Read the input using the command specified in the manual.
  3. Assign the second variable the value multiplied by two.
  4. Display the result.
  5. If there are several inputs, place the actions inside the documented loop.

This plan does not impose an arbitrary stopping condition. A sentinel or item count must be specified by the exercise.

Trace execution before expanding the program

For the square calculation, follow one line at a time: input supplies n, multiplication computes the value, and output displays it. Try 0, a small positive integer, and a negative value if the exercise domain allows it. These cases check whether the algorithm depends on a range the prompt never stated.

08 · study and debugging

Testing Kumir programs

Test an algorithm with small inputs and use environment messages to locate syntax or execution errors. Step-by-step execution helps check types, conditions, and intermediate values.

  • Try zero and negative values when the domain allows them.
  • Test both outcomes of a condition.
  • Check loop counts and the counter’s value at each step.
  • For performer tasks, begin with the original scenario.
  • Read the performer documentation before using a specialized action.

A successful run does not guarantee a solution covers every scenario. Compare the result with the task specification.

A debugging checklist

The suite's editor checks written programs continuously and can point to problems beside the code. Treat a diagnostic as a clue: inspect the marked line, its declaration, and the construct that contains it. Do not fix only the first underline without checking whether an earlier line left a block unfinished.

  1. Run an untouched official example to recognize the environment setup.
  2. Start with the simplest input values.
  3. Follow assignments and conditions step by step.
  4. Change one instruction at a time and repeat the same case.
  5. For a performer task, restore the initial world before comparing results.

Keep the Kumir version, selected performer, and test input with the exercise. This helps distinguish an algorithm problem from a difference between packages or course materials.

09 · versions and scope

Versions and variants

The official NIISI page and project papers discuss different suite versions. Menus, libraries, performers, and syntax may have changed between Kumir 1.x, Kumir 2.x, and operating-system packages.

This reference uses documented school constructs as a general guide and should be checked against the manual for the specific installation. Kumir is under evaluation; this manual does not indicate that Potoo IDE has a Kumir interpreter.

What to confirm before sharing a program

The Kumir family includes more than one generation and different distributions. A file may depend on words, libraries, or performers that another installation does not have. When sharing an exercise, state the version and manual used, include any required external resource, and describe the performer’s initial world.

The official NIISI page presents the suite as a school environment for learning algorithms and programming and lists packages for multiple systems. That does not remove version differences: confirm on the official portal which package matches the course and use its accompanying manual.

Reading and execution reference

Structures and executors map

Kumir combines a school algorithmic language with its environment and executor modules. The language provides sequence, data, and control; an executor adds commands and observations specific to a task. NIISI’s technical paper on Kumir 2.x describes this integration between the language and executors, while the official site distributes packages and manuals by version.
