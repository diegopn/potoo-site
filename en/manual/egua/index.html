01 · language and reference

Overview and version

Égua is an interpreted programming language whose syntax and messages use Portuguese vocabulary. It brings together imperative programming, functions as values, and object-oriented programming. The official interpreter walks the program structure to execute it; the project distributes a command-line interface and a browser-based experience.

This manual brings the official topics together as a continuous reference: it starts with the form of a source file, follows the rules that affect expression results, and covers built-in functions, libraries, and debugging strategies. Accented names are part of the language: write função, senão, padrão, and aleatório with the spelling shown.

Basis for this edition: official version 1.3.16 and documentation checked on November 17, 2026. The web documentation changes over time; this manual identifies the interpreter version when a rule depends on its implementation.

02 · execution environment

Execution environments

The same algorithm can be explored in a browser editor or run as a file with Node.js. The official project specifies Node.js 18 or later for installation through the command line.

EnvironmentGetting startedUseful for

Local fileInstall the official package with npm i -g egua, then run egua program.egua.Saving programs as .egua files and running them from a terminal.
REPLRun egua without a file argument.Trying expressions and small instructions interactively.

A minimal file contains an output instruction:

escreva("Hello, world!");

The REPL keeps an interactive session, while running a file processes the contents of the file you provide. For programs that must be reproducible later, save the source in a file and record which interpreter version you used.

03 · code form

Writing and structure

A source file combines declarations, instructions, and blocks enclosed in braces. Indentation does not define blocks; braces do. End simple declarations and instructions with a semicolon. The expressions in a para header are also separated by semicolons.

ElementFormHow to read it
Line comment// noteThe interpreter ignores the rest of the line.
Declarationvar total = 0;Creates a name; the initial expression is optional.
Assignmenttotal = total + 1;Updates a variable or an accessible property/index.
Callescreva(total);Calls a function with arguments in parentheses.
Block{ ... }Groups instructions and creates a local scope.
Text"Olá" or 'Olá'Uses single or double quotes.

Identifiers are case-sensitive. In the reference version, they may begin with an underscore, a Latin letter, or accented letters used in Portuguese; later characters may also include digits. Do not use a reserved word as a variable name. Documented comments use //; do not assume that block comments in the form /* ... */ are accepted.

// Keep calculation separate from presentation.
var raio = 3;
var area = 3.14159 * raio ** 2;
escreva(area);

escreva receives one expression and displays its value. To print several items, use separate calls or join text with +; do not treat the function as a multi-argument print list.

04 · state and scope

Variables and scope

var declares a name without a type annotation. The type comes from the stored value and can change when a new assignment is made. Without an initializer, the variable receives nulo. Assignment uses =; equality comparison uses ==.

var tentativas;          // nulo
tentativas = 0;
tentativas = tentativas + 1;
escreva(tentativas);     // 1

Scope tells you where a name can be read. A declaration outside blocks is global. A declaration inside a block is local to it; nested blocks can read and update outer names. Declaring the same name in an inner block creates a local name that temporarily hides the outer one.

var mensagem = "fora";
{
  var mensagem = "dentro";
  escreva(mensagem); // dentro
}
escreva(mensagem);   // fora

Functions also create scopes. Their parameters are local names, and an anonymous function can use a value available in the context where it was created. This closure over its context lets you make specialized operations without passing every value as an explicit argument:

var fator = 3;
var multiplicar = função(valor) {
  retorna valor * fator;
};
escreva(multiplicar(4)); // 12

Do not read a local variable in its own initializer. First declare it with a valid value, then update it. To prevent accidental shadowing, choose different names for accumulators, parameters, and variables in nested blocks.

05 · values and collections

Types and collections

Égua does not require type declarations. Its basic values and commonly used collections are:

TypeExamplesUse and detail
Number12, 3.5Integers and decimal numbers use the same numeric type.
Text"Égua", 'Lógica'A character sequence in single or double quotes.
Logicalverdadeiro, falsoValues used directly in conditions.
NullnuloAbsence of a specific value; also the initial value of var without an initializer.
List[8, "A", falso]An ordered, heterogeneous collection accessed by numeric index.
Dictionary{"nome": "Ana"}Associates keys with values; read a value by its key.

Text, lists, and dictionaries

Text and list indices start at zero. Text also accepts negative indices counted from the end: -1 denotes the last character. The official documentation describes an error when reading a list position that does not exist. Assigning beyond the end grows the list; skipped positions become nulo.

OperationExampleEffect
Read a listnotas[0]Gets the first item. A missing index signals an error.
Replace an itemnotas[1] = 7;Replaces the existing item at index 1.
Grow a listnotas[3] = 9;Creates positions through index 3; gaps become nulo.
Read text"abc"[-1]Gets the last character, "c".
Read a dictionaryaluna["nome"]Gets the value associated with the key.
var notas = [8, 6.5];
notas[3] = 9;
escreva(notas); // [8, 6.5, nulo, 9]

var aluna = {"nome": "Ana", "turma": 2};
escreva(aluna["nome"]); // Ana

Use lists when item position and order matter; use dictionaries when a key describes the data. The em operator tests whether a value belongs to a list, whether a character occurs in text, or whether a key exists in a dictionary.

06 · calculation and evaluation

Expressions and precedence

An expression combines values, names, calls, and operators. Parentheses make intent explicit. The table summarizes operator groups in version 1.3.16; higher rows are evaluated before lower rows.

GroupFormsPractical rule
Arithmetic** * / % + -Power, multiplication, division, remainder, addition, and subtraction.
Numeric comparison> >= < <=Compares two numbers and produces a logical value.
Equality== !=Compares type and value; 4 == "4" evaluates to falso. In implementation 1.3.16, lists, dictionaries, and instances compare by identity.
Logicale ouShort-circuit evaluation: e skips the right side when the left is false; ou skips it when the left is true.
MembershipemTests an item in a list/text or a key in a dictionary.
Bits! ~ & ^ | << >>! negates truthiness; ~ and the other operators act on numeric bits.
Assignment=Stores a value; assignment associates to the right, so a = b = 3 means a = (b = 3).
OrderOperatorsGrouping example
1 · highestParentheses, calls, property access, and indexingobjeto.metodo(x)[0]
2Unary - ! ~-(x)
3**2 ** 3
4* / %a * b / c
5+ -a + b - c
6–8<< >>, then &, then | ^Shifts before bitwise combinations.
9–10> >= < <=, then == !=Numeric comparison before equality.
11–13em, then e, then ouMembership before conjunction and disjunction.
14 · lowest=Assignment; associates to the right: a = b = 3 means a = (b = 3).

In the implementation tagged 1.3.16, chains of powers group from left to right: 2 ** 3 ** 2 means (2 ** 3) ** 2. Use parentheses if an exercise requires another grouping. The + operator accepts two numbers or two text values; mixing a number and text raises an error instead of converting automatically. In implementation 1.3.16, lists, dictionaries, and instances compare by identity. Combine separate relational tests with e; do not chain comparisons such as 1 < x < 10.

Truthiness matters outside comparisons too: only falso and nulo are false; numbers, text, lists, and dictionaries, including empty ones, are true. e and ou return the selected operand, which is not necessarily one of the logical literals. Use a comparison when the result must explicitly be verdadeiro or falso.

07 · execution flow

Decisions and repetition

Conditions choose which block runs; loops repeat a block; selectors choose among several cases. Braces delimit blocks, which may contain other blocks.

FormBehaviorUse it for
se (condição) { ... }Runs the block when the condition is true.A binary decision or a primary case.
senãose (condição)Tests another condition if earlier ones failed.Ordered classification ranges; this reserved form is written without a space.
senão { ... }Runs when no earlier branch was selected.Handling all remaining cases.
enquanto (condição) { ... }Tests before each iteration; may run zero times.Repeating until a condition becomes false.
para (início; teste; passo) { ... }Runs initialization once, tests before the body, then applies the step.Counting or traversing with a predictable update.
fazer { ... } enquanto (condição)Runs the body first and tests afterward; runs at least once.Repeating an action that must happen before the first test.
pausa;Ends the current loop or an escolha selection.Stopping after finding an item.
continua;Skips the rest of the body and starts the next iteration.Skipping an item without ending the loop.
escolha / caso / padrãoCompares an expression with each case; padrão handles no match.Selecting an action from discrete alternatives.
tente / pegue / senão / finalmenteLets a program handle a failure, run an optional success branch, and perform a final step.Imports or operations that can fail at runtime.
var notas = [8, 5.5, 9];
para (var i = 0; i < tamanho(notas); i = i + 1) {
  se (notas[i] >= 7) {
    escreva("Aprovada");
  } senãose (notas[i] >= 5) {
    escreva("Recuperação");
  } senão {
    escreva("Reprovada");
  }
}

Each of the three parts of para can be omitted independently. An omitted test supplies no stopping condition, so the loop continues until the body ends it with pausa. When debugging, record the initial value, test, update, and number of iterations. In escolha, cases use strict equality; more than one case can run if multiple labels have the same value. pausa ends the selection; without padrão, no action runs when nothing matches.

The web reference shows a semicolon after its fazer ... enquanto example, but the parser in tag 1.3.16 does not consume that terminator as part of the loop. There is another spelling difference: the current web guide writes senão se with a space, while the tagged lexer reserves senãose as one word. Examples in this edition follow the form accepted by the tagged interpreter. Do not mix conventions from different versions.

08 · composition and reuse

Functions and parameters

A named function uses função, a name, parameters, and a block. It can perform actions, return a value with retorna, or end without a value. Call it with parentheses and positional arguments; this example receives two values and returns a reusable result.

função média(a, b) {
  retorna (a + b) / 2;
}
var resultado = média(8, 10);
escreva(resultado); // 9

A return ends the function at that point. Without a value-returning statement, the call produces nulo. An anonymous function uses the same keyword, but can be stored in a variable or passed as an argument. This is useful with mapear, filtrar, and reduzir, which take a transformation, test, or accumulation function.

var dobrados = mapear([1, 2, 3], função(n) {
  retorna n * 2;
});
escreva(dobrados); // [2, 4, 6]

The version 1.3.16 grammar also accepts parameters with a simple default value and a final parameter prefixed by * to collect remaining arguments. Since these details do not appear in every official guide, check them in the specific interpreter before using them in shared teaching material:

FormExampleEffect
Default valuefunção saudar(nome = "visitante") { ... }Uses the provided value when no argument is supplied.
Remaining argumentsfunção somar(*valores) { ... }Groups the remaining arguments in a list in the final parameter.

Keep calls easy to review: use few parameters, choose names that explain each argument, and return values that can be tested separately. A calculation function does not also need to print; separating calculation and presentation makes the result reusable.

09 · object-oriented programming

Classes and objects

classe describes methods and can inherit from a base class with herda. Calling the class name creates an instance. Methods are declared inside the braces without writing função; the construtor method receives the arguments used during creation. Inside a method, isto refers to the current instance.

classe Contador {
  construtor(valor_inicial) {
    isto.valor = valor_inicial;
  }

  avançar() {
    isto.valor = isto.valor + 1;
    retorna isto.valor;
  }
}

var contador = Contador(2);
escreva(contador.avançar()); // 3

A property can be read or updated with a dot, as in contador.valor. Inheritance reuses methods; super accesses a method defined in the parent class:

classe Animal {
  apresentar() {
    retorna "animal";
  }
}

classe Cachorro herda Animal {
  apresentar() {
    retorna super.apresentar() + " doméstico";
  }
}

var bicho = Cachorro();
escreva(bicho.apresentar());

Use a class when several instances need independent state and related operations. If a problem only transforms an input into an output, a function usually makes the dependency clearer. The documentation does not define visibility keywords such as público or privado; do not assign undocumented encapsulation rules to properties.

Avoid these calls in long loops. In the time library, use the explicit format and test boundary dates such as the last day of a month.

var matemática = importar("matemática");
var notas = [6, 8, 10];
escreva(matemática.média(notas)); // 8

Importing a library makes the program's dependency explicit. Import once and reuse the module instead of calling importar on each loop iteration.

12 · worked example

Guided program: classify and summarize grades

This example combines a named function, a filter, a reduction, a condition, and conversion to text. Before running it, identify the input data, the passing rule, and the case where the filtered list is empty.

função aprovado(nota) {
  retorna nota >= 7;
}

var notas = [8, 6, 9.5, 7, 5];
var aprovadas = filtrar(notas, aprovado);
var soma = reduzir(aprovadas, função(total, nota) {
  retorna total + nota;
}, 0);

escreva("Number of grades:");
escreva(tamanho(notas));
escreva("Passing grades:");
escreva(aprovadas);

se (tamanho(aprovadas) > 0) {
  var média = soma / tamanho(aprovadas);
  escreva("Average of passing grades:");
  escreva(média);
} senão {
  escreva("No grade reached the threshold.");
}

The accumulator for reduzir starts at zero and adds each passing grade to the previous total. For this input, the filter returns [8, 9.5, 7], the accumulator ends at 24.5, and the average is about 8.17.

StepObserved valueWhy it matters
Input[8, 6, 9.5, 7, 5]Original list, preserved by the filter.
aprovado predicateverdadeiro for 8, 9.5, and 7The rule is defined in one place.
filtrar result[8, 9.5, 7]Items for which the function returns true.
Reduction0 → 8 → 17.5 → 24.5Shows how each item changes the accumulator.
Result24.5 / 3 ≈ 8.17Division happens only when at least one grade passes.

Extend the exercise by counting grades below 7 with another filter, finding the highest grade with the math library, or replacing the input list. Also test []: the alternate branch must run without trying to divide by zero.

13 · reading failures

Errors and debugging

Separate writing errors, name-resolution errors, and runtime errors. A message often points to the token or line closest to the problem; the cause may be in the previous instruction, such as a missing brace or semicolon.

SymptomWhat to checkTypical fix
Expected ; or }End of the declaration and opening/closing of the previous block.End each simple instruction and check brace pairs.
Unknown nameSpelling, accents, and the variable's scope.Declare before use; verify matemática and other accented names.
A variable cannot be read in its initializerA declaration such as var x = x;.Initialize from another value or assign after declaration.
+ fails at runtimeOne side is a number and the other is text, or the types are incompatible.Convert explicitly with texto/real/inteiro when appropriate.
List index signals an errorEmpty list, upper bound, and index calculation.Check tamanho(lista) and test the first/last position.
pausa or continua outside a loopIs the block inside enquanto, para, or fazer?Move the control statement into the corresponding loop body.
Import or HTTP call failsModule name, accents, URL, network, and response status.Check the module and handle network failures in pegue.
  1. Reduce the program to the smallest sequence that still reproduces the problem.
  2. Display intermediate values with escreva, one expression per call.
  3. Test boundaries: empty list, one item, first/last index, and both branches of a condition.
  4. Change one rule at a time and repeat the same input to identify which change corrected the result.
  5. Record the interpreter version, file, and input; this helps identify version differences.

14 · guided practice

Study path

A short sequence that reuses the same ideas in progressively larger problems:

  1. Output and expressions: calculate a circle's area and perimeter. Check multiplication and power precedence against a manual calculation.
  2. Decisions: classify a grade in three ranges. Try values below 5, from 5 to below 7, and at least 7 to cover each branch.
  3. Repetition: traverse a list by index. Record the value of i, the stopping condition, and the number of iterations.
  4. Functions: move the passing rule into a function that returns a logical value. Test it alone before applying it to the list.
  5. Functional programming: filter and average the list with built-ins; handle an empty list explicitly.
  6. Objects and modules: create a class for state that changes over time and import only the library needed for the exercise.

At each stage, also write a case that should fail or take another branch. Explaining the expected value before execution is a simple way to check that the algorithm represents the problem.

15 · compatibility scope

Version and scope of this reference

Égua changes along with its interpreter. The official manual, browser application, published package, and independent implementations may not expose exactly the same feature set. This page describes the official language using version 1.3.16 as its baseline and identifies details found in that version's source when the web guide is brief.

In particular, the function and library catalog follows the official pages; details about precedence, optional parameters, and loop terminators were also checked against the parser and interpreter tagged 1.3.16. An implementation that supports only part of the language may not recognize lists, classes, exceptions, imports, or the libraries described here. Check the compatibility information for the environment that will run your program before reusing these examples.
