01 · overview

About SL

SL introduces programming concepts in a textual form that is readable to Spanish-speaking students. Project materials describe a learning environment for constructing algorithms, testing execution, and studying the parts of a solution.

SL is not simply a translation of another pseudolanguage: its grammar, reserved words, and library should be read from SL documentation. This reference highlights concepts in material from the Universidad Nacional de Asunción and avoids mixing in commands from other systems.

Status in Potoo IDE: SL is under evaluation. The examples on this page refer to the external project and do not claim compatibility with the app.

02 · background

Project and teaching purpose

The official material is associated with the Facultad Politécnica at the Universidad Nacional de Asunción. It presents SL as a resource for teaching algorithms and includes the SLE environment, documents, examples, and supporting material.

The language was designed for practicing introductory concepts:

  • describe a sequence of instructions with an explicit beginning and end;
  • declare data and compose expressions;
  • read input and display results;
  • control decisions and repetition;
  • organize calculations into functions and procedures.

The official portal and project book are the references for syntax details and for features in a specific version of SLE.

03 · program structure

Program structure

A simple program can declare variables, begin its executable sequence, receive data, calculate a result, and finish. The project documentation uses Spanish keywords and lowercase forms in its examples. This fragment follows the introductory format shown in the material:

var
    n, resultado : numerico
inicio
    leer(n)
    resultado = n * n
    imprimir(resultado)
fin

var introduces declarations, inicio opens the body, and fin ends the program. Program, variable, and procedure names follow the identifier rules in the book.

04 · data and operators

Variables, types, and collections

SL documents numeric and text values and logical values, along with structures for grouping data and working with collections. Exact type names and index rules should follow the official manual for the relevant version.

ConceptTeaching use
ScalarsRepresent numbers, characters, or conditions.
Arrays and matricesStore sequences of elements accessed by index.
RecordsGroup named fields with their own types.
ExpressionsCombine arithmetic, relational, and logical operators.

Choose meaningful variable names and an appropriate type. Before accessing an array position or record field, identify the declared bounds and structure.

05 · interaction

Input, output, and calculations

Project examples use read and print instructions to connect an algorithm to data supplied by the person running it. An expression can combine values and store a calculation before displaying it.

var
    base, altura, area : numerico
inicio
    imprimir("Ingrese la base y la altura:")
    leer(base, altura)
    area = base * altura
    imprimir(area)
fin

The example declares its data and separates input, calculation, and output. Check the book for literal and punctuation details in the SLE version used by the class.

Separating input, processing, and output makes it easier to test the calculation without confusing an input problem with a formula error.

06 · control flow

Decisions, loops, and procedures

SL includes structures for selecting a path, repeating commands, and reusing operations. Project documentation covers conditionals, counted or conditional loops, functions, and procedures. Exact reserved words depend on the construct and should be copied from the official manual rather than another language.

  • Decision: execute a block based on a logical expression.
  • Repetition: repeat instructions a controlled number of times or until a condition.
  • Function: calculate and return a result.
  • Procedure: name a sequence of actions that can be called elsewhere.

When writing a loop, identify the variable or condition that changes and explain why repetition stops. When dividing a problem into routines, define the values each receives and the result or effect it produces.

07 · worked example

Calculate the average of two marks

A simple average practices data, input, expressions, and output. First declare both marks and the result using suitable types. Then read each value, calculate their sum divided by two, and display the average.

var
    nota1, nota2, promedio : numerico
inicio
    leer(nota1)
    leer(nota2)
    promedio = (nota1 + nota2) / 2
    imprimir(promedio)
fin

To extend the example, validate that marks fall within the interval allowed by the exercise. A condition can choose a message for pass or fail; a loop can repeat input while a mark is invalid. The pass threshold belongs to the exercise and should not be assumed.

08 · study and debugging

Practising with SL

Use the official portal’s environment and examples to confirm syntax. Start with small programs and run them using known inputs. If the SLE version provides step-by-step execution, advance one instruction at a time and watch relevant variables.

  • Test typical inputs and boundaries defined by the problem.
  • Check types before mixing numbers and text in an expression.
  • For arrays, verify the first and last index used.
  • For procedures, compare each argument with its parameter’s documented purpose.
  • When an error appears, locate the first incompatible statement and confirm the keyword in the manual.

The book and official materials give full conventions and exercises that a summary cannot replace. Use this page as a map of concepts, not a substitute for the specification of an installation.

09 · versions and scope

Implementation and limits

The SL ecosystem includes the language and SLE, but the portal may offer different versions and files over time. Interface, debugging, library, and syntax details should be confirmed in the package actually installed.

This reference summarizes publicly documented feature families. It does not promise that every historical construct is available in every version or that an SL program runs unchanged in another interpreter. SL remains under evaluation as a future possibility for Potoo IDE.

10 · syntax and reading

Identifiers, operators, and writing rules

The SL book specifies three basic types: numerico, cadena, and logico. The numeric type represents both integers and real values; strings have dynamic length; arrays and records can be built from these types. The book describes strict type compatibility and structurally checked aggregate types.

FormDocumented use
numericoIntegers and real values under one basic type.
cadenaResizable text; + concatenates two strings.
logicoConditions used by selections and loops.
vector, matriz, registroAggregate structures, including multidimensional arrays and records with fields.

Identifiers are case-sensitive, start with a letter or underscore, and can contain up to 32 characters. The book allows ñ but not accented letters in identifiers; reserved words must be lowercase. These details are common sources of errors when copying examples.

Assignments use =; comparisons include == for equality and <> for inequality. Expressions can also use <, >, <=, and >=, together with the logical operators and, or, and not. Statements may span lines; multiple statements on one line use semicolons.

The two repetition forms highlight useful execution differences: mientras tests before its body and may run zero times; repetir runs the body and only then tests hasta. In either form, identify which value changes and why the stopping condition will be reached.

var
    n : numerico
inicio
    n = 1
    repetir
        n = n + 1
    hasta (n >= 5)
    imprimir (n)
fin

11 · decomposition

Functions, procedures, and parameters

The book distinguishes functions, which return a value and can appear in expressions, from procedures, which perform actions without producing a result. Subroutines follow the main program and may declare local constants, types, and variables. A function declares its return type and uses retorna to provide the result:

subrutina cuadrado (n : numerico) retorna numerico
inicio
    retorna (n * n)
fin

Parameters can be passed by value or by reference. By value, the subroutine receives an initial copy; changing the parameter does not change the original argument. With ref, the routine receives a reference and its assignments change the variable supplied by the caller. Make this difference explicit in each subroutine's contract.

subrutina duplicar (ref valor : numerico)
inicio
    valor = valor * 2
fin

Variables declared in the main program are global; declarations inside a subroutine and formal parameters are local. A local name can hide a global name with the same spelling while the routine runs. Local scope helps make subroutines independent and also supports recursion, but it requires care when distinct values share an identifier.

When designing a function, list its parameters, result type, and boundary cases. For a procedure that takes a reference, note which argument it changes. Test the routine with small data before integrating it into the main algorithm.
