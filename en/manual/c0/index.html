01 · overview

What is C0

C0 was designed to teach imperative programming and data structures with syntax familiar to people who have seen C, but with a smaller set of features and more controlled rules. It appears in introductory courses at Carnegie Mellon University, including material for course 15-122.

The teaching goal is to make types, control flow, memory, and a function’s obligations explicit. Course material describes C0 as a safe subset of C with garbage collection, fixed-range integers, and contracts. The language specifies behavior so students do not rely on C’s undefined edge cases. It is not intended to accept every C program: a C file may depend on features that do not exist in C0.

Status in Potoo IDE: C0 is under evaluation. Carnegie Mellon’s environment and compiler tools are the references for running examples on this page.

02 · background

Origin and teaching goals

C0 was developed to support the teaching of programming and reasoning about memory. Its syntax resembles a language in the C family, while the design restricts constructs that can make a beginner’s program behavior harder to analyze.

The official reference organizes the language around functions, types, statements, and contracts. Courses use these tools to develop correct solutions and explain why a function works, rather than only obtaining an output for one test case.

  • Imperative programming: variables, assignments, calls, conditions, and loops.
  • Abstraction: functions and structs name operations and related data.
  • Reasoning about correctness: preconditions, postconditions, and invariants state what must hold.

03 · data and types

Types, values, and collections

C0 defines values and operations precisely so programs do not depend on C's undefined cases. The rules for int, text, arrays, and structs belong to the language; do not infer them from an ordinary C compiler.

Type or formWhat it representsRule to remember
intA 32-bit two's-complement integer word.Arithmetic is modulo 232; values wrap from the maximum to the minimum representable value.
boolOne of true and false.Conditions and contracts must produce a Boolean; && and || short-circuit.
charAn ASCII character, not Unicode.Comparisons use ASCII codes; literals use single quotes.
stringConstant text made from ASCII characters.\0 cannot appear in a literal; compare with library functions, not ==.
t[]A reference to an allocated array of values of type t.Create it with alloc_array(t, n); valid indices are 0 through n-1.
t*A pointer to a value of type t in memory; it may be NULL.alloc(t) creates the location; test p != NULL before *p to avoid a null-pointer failure.
struct sA named record with fields that can have different types.It is allocated in memory and used through a pointer, such as p->field; it is not copied by value like an int.
voidThe return type for a function with no result.Use it only for functions called as statements.

Arrays are small references to a fixed-length area. An access outside the bounds—a negative index or one greater than or equal to the length—causes a bounds violation and terminates the program. Automatic garbage collection handles arrays and structs that are no longer reachable; programs do not call free. This removes manual deallocation, but it does not make every access safe: bounds, null values, and relations between fields still require reasoning.

An integer is modular, not an unbounded-precision number: for example, incrementing the greatest representable int wraps to the least value. Integer division truncates toward zero; division by zero and the special case -2^31 / -1 raise an arithmetic error. If a task requires a narrower range, state it in the contract and check it before calculating.

04 · program structure

Functions, declarations, and blocks

A program is organized into functions. A signature declares the result type, function name, and parameter types; the body is enclosed in braces. Local declarations introduce values used in a block, and return ends a function with the expected result.

int square(int value) {
    return value * value;
}

int main() {
    int result = square(6);
    return 0;
}

The example shows a small pure function and a conventional entry function. The library and contract required for main may depend on the course’s compilation environment. Comments should explain purpose or a relevant decision, rather than replace a precise description of parameters and results.

05 · control flow

Decisions, loops, and calls

C0 provides the familiar statements of an imperative model: sequence, selection, repetition, function calls, and returns. Conditions are Boolean expressions. A loop must move toward its exit condition; informal reasoning about that progress helps avoid programs that never finish.

ConstructPurpose
if / elseChoose a block based on a condition.
whileRepeat while a condition remains true.
forGroup initialization, condition, and update in a counted loop.
returnProduce the result declared by a function signature.

Arrays, structs, and pointers represent collections and relationships between values. Each array access must stay within its valid bounds; going beyond them is a safety violation. Use contracts and invariants to justify indices and relationships between data, and do not assume invalid operations behave like they would in another C implementation.

06 · correctness

Contracts, invariants, and safety

Contracts record the conditions under which a function can be called and what it guarantees when it finishes. A precondition states an input requirement; a postcondition describes the result. A loop invariant summarizes a property that should remain true after every iteration.

  • Precondition: state bounds and relationships that arguments must satisfy.
  • Postcondition: relate the returned value to the problem the function solves.
  • Invariant: explain the meaning of state maintained during an iterative algorithm.
AnnotationWhat it specifiesDynamic check
//@requiresCondition that arguments must satisfy.Before the function body.
//@ensuresProperty of the result; may use \result.Before the function returns.
//@loop_invariantProperty that must hold during the loop.Every iteration, before the exit test.

The reference writes preconditions and postconditions in special comments, such as //@requires expression; and //@ensures expression;. In a postcondition, \result represents the returned value. Loop invariants use //@loop_invariant expression; and must be Boolean expressions. When dynamic checking is enabled, tools evaluate these contracts at points defined by the reference; writers remain responsible for correct contracts and bounds reasoning.

int maximum(int x, int y)
//@ensures \result >= x && \result >= y;
{
    if (x > y) {
        return x;
    } else {
        return y;
    }
}

07 · worked example

Plan a search function

Consider a function that looks for an integer in an array. Before implementing it, define what “found” means: return a valid index when the value occurs and report absence otherwise. The type and value used to represent “not found” must follow the exercise’s convention.

  1. Declare parameters for the array, its size, and the value to find.
  2. Decide whether size zero is allowed and what condition the array must satisfy.
  3. Visit valid indices in order and compare each element.
  4. Return the index as soon as a match is found.
  5. After the loop, return the documented absence marker.

A postcondition can relate the returned index to the matching element. If the result reports absence, the postcondition should state that no element in the range matches. This specification covers empty arrays and repeated values as well.

08 · study and debugging

How to study and debug C0

Compile small pieces as you learn. For each function, write down its signature, input cases, and the meaning of its expected result. Then trace execution with a variable table; for collection algorithms, include the index and the range already processed.

  • Test boundary values: zero, minimum size, first index, and last index.
  • Exercise both true and false paths in every condition.
  • Include empty, one-element, and repeated-value arrays when the contract allows them.
  • Read verifier or compiler messages alongside the relevant precondition and invariant.

A program that compiles can still solve the wrong problem. Compare its output with an independent calculation and test cases that exercise every branch.

09 · guided traversal

Arrays, contracts, and memory safety

A function that sums an array prefix must relate the array length, the current index, and the total already computed. The precondition below requires n to fit the array; the invariant keeps the index within the allowed range.

int sum_prefix(int[] values, int n)
//@requires 0 <= n && n <= \length(values);
{
    int i = 0;
    int total = 0;
    while (i < n)
    //@loop_invariant 0 <= i && i <= n;
    {
        total = total + values[i];
        i = i + 1;
    }
    return total;
}

C0 arrays have a fixed length set at allocation and use zero-based indices. Since \length(values) is allowed only in contracts, code receives n as an argument and the caller guarantees that it does not exceed the actual length.

This main creates a three-element array and calls the function:

int main() {
    int[] values = alloc_array(int, 3);
    values[0] = 4;
    values[1] = 2;
    values[2] = 5;
    return sum_prefix(values, 3);
}

The written invariant proves only the index bound; the correctness argument must also relate total to the elements already processed. 10 · allocation and failures

Allocation, pointers, and runtime errors

C0 uses typed allocation: alloc(t) creates space for a value of type t, and alloc_array(t, n) creates an array of fixed length. Garbage collection reclaims objects that are no longer reachable, so programs do not call free. This simplifies deallocation, but memory is finite and bounds or pointer checks are still necessary.

FormRule and limitHow to reason about it
alloc_array(t, n)n must be nonnegative; the length is fixed. The language does not specify one universal numeric maximum.Use indices from 0 to n - 1. A zero-length array has no accessible positions. The environment can run out of memory.
alloc(t)Allocates one typed cell; struct fields start with their types' default values.Initialize fields according to the program's meaning. If memory runs out, execution may abort; allocation does not signal this by returning NULL.
t* and NULLNULL is the default pointer value and can represent the absence of an object.Before using *p or p->field, establish that p != NULL. An alloc that completes normally provides a pointer to the allocated object.
Garbage collectionUnreachable objects may be reclaimed by the collector.No free call is needed, but reachable references still use memory and a program can exhaust it.

The bound n <= 1000 in the program below is a local design choice: together with validation that every element is between 0 and 1000, it keeps the sum within a safe int range. It is not a C0 language limit. The practical maximum allocation depends on available memory; the CMU reference notes that even a correct program may abort when memory runs out.

This example combines an array, a struct, a pointer, preconditions, postconditions, a loop invariant, and explicit rejection of data outside the function's domain. The sum_prefix function was defined in the previous section.

struct summary {
    int count;
    int total;
};
typedef struct summary* summary;

summary summarize(int[] values, int n)
//@requires 0 <= n && n <= \length(values) && n <= 1000;
//@ensures \result != NULL;
//@ensures \result->count == n;
//@ensures \result->total == sum_prefix(values, n);
{
    if (n < 0 || n > 1000) {
        error("n must be between 0 and 1000");
    }
    summary result = alloc(struct summary);
    result->count = 0;
    result->total = 0;
    int i = 0;
    while (i < n)
    //@loop_invariant 0 <= i && i <= n;
    //@loop_invariant result->count == i;
    //@loop_invariant result->total == sum_prefix(values, i);
    //@loop_invariant 0 <= result->total && result->total <= 1000 * i;
    {
        if (values[i] < 0 || values[i] > 1000) {
            error("value must be between 0 and 1000");
        }
        result->total = result->total + values[i];
        result->count = result->count + 1;
        i = i + 1;
    }
    return result;
}

int main() {
    int[] values = alloc_array(int, 3);
    values[0] = 4;
    values[1] = 2;
    values[2] = 5;
    summary report = summarize(values, 3);
    return report->total;
}

alloc(struct summary) provides a pointer to the struct if allocation completes normally. The program explicitly writes count and total before relying on them; report->total then accesses a field through a pointer. \result in the postconditions names the returned pointer, and the call to the earlier function specifies exactly which sum it must contain.

At the start of each pass, count == i, so they advance together. The invariant with sum_prefix(values, i) states what the accumulated total means; its numeric bound follows because each accepted value is between 0 and 1000 and prevents overflow. The postcondition guarantees that the function returns a count of all n elements and the same total as sum_prefix. With n = 0, no element is read and the function returns a struct whose count and total are both zero. main returns 11; how the course environment displays that value depends on the tool being used.

Identify the source of a failure

Not all failures are the same kind. The table separates runtime errors from properties checked only when the tool enables dynamic contract checking.

SituationExampleBehavior
Array index out of boundsvalues[n] for an array of length nA bounds violation terminates the program; the last valid index is n - 1.
Null pointer*p or p->field when p == NULLA runtime exception terminates the program. Check optional pointers before dereferencing them.
Invalid arithmetic operationDivision by zero, INT_MIN / -1, or shift count outside 0 to 31Raises an arithmetic exception. Addition, subtraction, and multiplication use 32-bit modular arithmetic.
Out of memoryAn allocation does not fit in available memoryEven a correct program may abort. C0 gives no universal ceiling and alloc does not return NULL to report failure.
False precondition, postcondition, or invariant//@requires, //@ensures, or //@loop_invariantThe tool reports the violation when dynamic checking is enabled; a build without that option may not evaluate it.
Internal failureassert(e) when e is falseAssertions always run and abort the computation when the condition is false.
Rejected inputerror("message")Prints the message and terminates the program; use it for a known invalid condition, as in the example.

For debugging, reproduce one failure class at a time: test an empty array, the last valid index, and the first invalid one; test a null optional pointer and an allocated pointer; exercise accepted and rejected input; and compare a verifier message with the contract meant to protect that case. Garbage collection neither fixes these errors nor proves that a struct satisfies the algorithm's rules.

11 · version and scope

Scope of this reference

The official CMU reference linked here is C0.14, revision 707, dated February 18, 2025. It separates the base language from the C1 extension, which contains experimental features enabled for .c1 files. This page describes base C0; check the version used by your course.

This page is limited to introductory ideas shared by the references consulted. It does not claim C0 support in Potoo IDE and does not replace the manual for the version used in class. The language remains under evaluation as a project candidate.
