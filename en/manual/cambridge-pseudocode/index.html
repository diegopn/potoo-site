01 · overview

What is Cambridge pseudocode

Cambridge pseudocode is a convention used to present algorithms in Computer Science courses and assessments. English keywords and delimited blocks make control flow clear without requiring a choice of executable programming language.

The teacher guide specifies expected forms in answers and course material. In exam questions, use the notation supplied by Cambridge International, even if another programming language is more familiar.

Status in Potoo IDE: the notation is under evaluation. Having this manual does not mean programs written in it can run in the app.

02 · assessment context

Guides and exam years

Cambridge International publishes pseudocode guides linked to its study programmes. The applicable edition depends on the exam year; updates may change examples, rules, or teacher recommendations.

For 2026 exams, this page follows the 2026 guide. The published 2027–2029 guide applies to exams in those three years. Match your assessment year to the cover of the PDF before preparing answers; a later edition should not be applied retroactively to an earlier exam.

Pseudocode exists to make algorithm writing readable and consistent for writers and markers, not to define a software runtime.

03 · data

Declarations, types, and assignment

The guide represents declarations using DECLARE, an identifier, a colon, and a type. Assignment uses an arrow pointing to the variable. Common types include integers, real numbers, characters, strings, and Boolean values.

DECLARE mark : INTEGER
DECLARE passed : BOOLEAN
mark ← 72
passed ← mark >= 50
TypeTypical use
INTEGERWhole-number values.
REALNumeric values with a fractional part.
CHAR / STRINGA character or a sequence of text.
BOOLEANTrue or false conditions.

The guide also specifies array declarations and, where required by the course, other structures. Write types and bounds as shown in the current document.

04 · input and output

Reading and displaying data

INPUT receives a value and OUTPUT displays text or a result. In a written answer, show each input and output operation explicitly so that the algorithm’s interaction is clear.

DECLARE name : STRING
INPUT name
OUTPUT "Hello, ", name

When tracing output, follow the order of arguments and the guide’s conventions for separating or joining values. Do not confuse assessment notation with the input syntax of a particular console.

05 · control flow

Selection and loops

Control words mark the beginning and end of each block. Cambridge pseudocode includes selection with IF, alternatives, and multi-way selection, along with FOR, WHILE, and REPEAT loops.

IF mark >= 50 THEN
    OUTPUT "Pass"
ELSE
    OUTPUT "Retry"
ENDIF

For a FOR loop, state the range and counter direction; a WHILE condition is checked before its body; with REPEAT, check that the condition is evaluated after the statements as defined in the guide. Write every closing delimiter correctly.

06 · collections

Arrays and structures

Arrays store multiple values of one type and are accessed by index. The guide allows declarations with dimensions and bounds; do not assume every array starts at zero or one without reading its declaration.

The pseudocode also documents records and data structures when the course level requires them. For each collection:

  • record its type and dimensions;
  • check that each index lies within its bounds;
  • distinguish the array’s size from the current position;
  • when traversing, verify the counter’s first and last values.

Exam answers should keep bounds consistent between the declaration, accesses, and loop.

ElementReadingCheck
Declaration ARRAY[1:5]Inclusive bounds from 1 to 5.There are five positions; the lower index is declared.
A[index]Element at one position.Check that index lies within the bounds.
A[row, column]Element in a matrix.Validate each dimension separately.

07 · routines

Procedures and functions

Procedures name reusable actions; functions calculate and return a value. Headers identify parameters and, for a function, its return type according to the guide. Calls transfer control to the routine and continue after it returns.

When writing a routine, describe its purpose and choose enough parameters to avoid dependence on external variables. Parameter passing and variable scope are assessed according to the rules published for that exam year.

Do not mix Cambridge pseudocode with declarations from Pascal, Python, or another assessment board’s pseudocode.

08 · worked example

Sum the elements of an array

To sum an array’s elements, initialize an accumulator, visit each valid position, and add the current element. The declaration below illustrates an array indexed from 1 to 5; use the bounds given by a question.

DECLARE numbers : ARRAY[1:5] OF INTEGER
DECLARE total : INTEGER
DECLARE index : INTEGER

total ← 0
FOR index ← 1 TO 5
    total ← total + numbers[index]
NEXT index
OUTPUT total

The example demonstrates assignment, indexing, and a loop. A complete answer must also show how numbers was read or assigned, as required by the problem. Trace the accumulator after each iteration to avoid missing the first or last element.

09 · complete walkthrough

From the problem statement to a class report

Consider a class of three students. The algorithm reads each name and integer mark, rejects marks outside 0 to 100, classifies the result, then reports all three classifications, the average, and the number of students who passed. A fixed limit of three makes the array and loop bounds explicit.

RequirementRule usedHow the program handles it
InputThree names and three integer marks from 0 to 100.An array stores three records; a loop reads each student.
ValidationA mark below 0 or above 100 is not accepted.REPEAT ... UNTIL repeats the input until the mark is within range.
Classification80–100: Distinction; 50–79: Pass; 0–49: Resit.A function checks the thresholds in descending order.
ReportShow each result, the average, and the number of passes.A procedure displays each record; accumulators calculate the summary.

The program combines forms described in the Cambridge 9618 guide for 2027–2029: declarations, records, arrays, input and output, selection, iteration, procedures, and functions. This is an original teaching exercise, not an official exam question or a program that runs in Potoo IDE.

Complete program

CONSTANT PassMark = 50
CONSTANT DistinctionMark = 80

TYPE StudentRecord
    DECLARE Name : STRING
    DECLARE Mark : INTEGER
    DECLARE Category : STRING
ENDTYPE

FUNCTION GetCategory(Mark : INTEGER) RETURNS STRING
    IF Mark < 0 OR Mark > 100 THEN
        RETURN "Invalid"
    ELSE
        IF Mark >= DistinctionMark THEN
            RETURN "Distinction"
        ELSE
            IF Mark >= PassMark THEN
                RETURN "Pass"
            ELSE
                RETURN "Resit"
            ENDIF
        ENDIF
    ENDIF
ENDFUNCTION

PROCEDURE DisplayStudent(Name : STRING, Mark : INTEGER, Category : STRING)
    OUTPUT Name, " - ", Mark, " - ", Category
ENDPROCEDURE

DECLARE Students : ARRAY[1:3] OF StudentRecord
DECLARE Index : INTEGER
DECLARE PassedCount : INTEGER
DECLARE TotalMarks : INTEGER
DECLARE ClassAverage : REAL

PassedCount ← 0
TotalMarks ← 0

FOR Index ← 1 TO 3
    OUTPUT "Student name:"
    INPUT Students[Index].Name
    REPEAT
        OUTPUT "Enter a mark from 0 to 100:"
        INPUT Students[Index].Mark
    UNTIL (Students[Index].Mark >= 0) AND (Students[Index].Mark <= 100)

    Students[Index].Category ← GetCategory(Students[Index].Mark)
    TotalMarks ← TotalMarks + Students[Index].Mark

    IF Students[Index].Mark >= PassMark THEN
        PassedCount ← PassedCount + 1
    ENDIF
NEXT Index

ClassAverage ← TotalMarks / 3

OUTPUT "Report:"
FOR Index ← 1 TO 3
    CALL DisplayStudent(Students[Index].Name,
                        Students[Index].Mark,
                        Students[Index].Category)
NEXT Index
OUTPUT "Class average: ", ClassAverage
OUTPUT "Passed: ", PassedCount, " of 3"

How the constructs fit together

ConstructResponsibilityWhat to check
StudentRecordGroups one student's name, mark, and classification.Access each field with dot notation.
Students[1:3]Stores the three records at indices 1 to 3.The declaration and loop bounds match.
GetCategoryReturns a classification as a function value.Check thresholds from highest to lowest; the function also guards against an invalid range.
DisplayStudentDisplays one result per call.A procedure call starts with CALL and is a complete statement.
REPEAT ... UNTILValidates a mark before it enters the summary.The condition is checked after input, so at least one attempt is made.
FOR, TotalMarks, and PassedCountVisit the array, add marks, and count passes./ produces a REAL even when both operands are integers.

In the first pass, TotalMarks and PassedCount are updated alongside each record. In the second pass, the program only displays the stored data. This separation avoids recalculating classifications and makes the report easier to check after all input has been read.

10 · exam responses

Writing and checking answers

Consistency matters as much as the algorithmic idea in an exam response. Use descriptive names, steady indentation, and block delimiters from the guide.

  • Declare variables and arrays before use when required.
  • Check that each variable’s type matches its assigned values.
  • Trace at least one typical case and a boundary case.
  • Check the stopping condition and counter update.
  • For functions, verify every return path.

Pseudocode communicates an algorithm; clarity and fidelity to the exam-year standard make it easier to read and assess.

11 · operators and selection

Operators and CASE selection

Cambridge operator conventions differ from those in some other languages: DIV gives the integer quotient, MOD the remainder, and <> means “not equal”. Comparisons produce a Boolean value; use parentheses when an expression combines several operations.

CASE organizes alternatives for one identifier. The ranges in this example assume marks use a scale from 0 to 100:

CASE OF Mark
    80 TO 100 : OUTPUT "Distinction"
    50 TO 79 : OUTPUT "Pass"
    OTHERWISE : OUTPUT "Resit"
ENDCASE

Cases are checked in sequence. When a value matches, its statements run and control continues after ENDCASE. If present, OTHERWISE comes last and handles values not matched earlier. Before writing ranges, check that they leave no gaps or overlaps for the data allowed by the question.

GroupFormsPurpose
Integer arithmeticDIV, MODInteger quotient and remainder.
Comparison=, <>, <, >, <=, >=Produces a BOOLEAN value.
LogicAND, OR, NOTCombines or negates Boolean conditions.

12 · strings

Use the supplied string functions

The guide describes functions such as LENGTH, MID, and RIGHT to count characters, extract a section, or obtain the end of a string. In exams, the string-manipulation functions you need are supplied in the question; do not assume their signatures match those in another language.

DECLARE ItemCode : STRING
INPUT ItemCode
IF LENGTH(ItemCode) >= 3 THEN
    OUTPUT MID(ItemCode, 1, 3)
ELSE
    OUTPUT ItemCode
ENDIF

The condition protects the substring operation when the text has fewer than three characters. When solving a question, identify in the function description where selection starts and how many characters it requests. Then test a string exactly at the minimum length, a longer one, and a short case.

FunctionResultExample
LENGTH(text)Number of characters.LENGTH("Happy Days") returns 10.
MID(text, start, count)Substring of the given length.MID("ABCDEFGH", 2, 3) returns BCD.
RIGHT(text, count)The final characters.RIGHT("ABCDEFGH", 3) returns FGH.

13 · subprograms

Choose pass-by-value or pass-by-reference

Procedures receive parameters by value unless the guide or question specifies another mode. With pass-by-value, a parameter acts as a local copy. BYREF signals that a procedure can change the variable supplied at the call.

PROCEDURE AddBonus(BYREF Score : INTEGER, BYVAL Bonus : INTEGER)
    Score ← Score + Bonus
ENDPROCEDURE
CALL AddBonus(CurrentScore, 5)

After the call, CurrentScore has increased by five because Score is passed by reference; Bonus remains a pass-by-value parameter. A procedure call is a complete statement and begins with CALL.

A function is different: it returns one value, and its call appears in an expression or assignment. The guide says not to use CALL for functions or pass their parameters by reference. When reading a routine, identify its kind, its parameters, and where its result is used.

FormEffectUse
Default / BYVALThe procedure receives the argument’s value.Local changes do not replace the original variable.
BYREFThe parameter refers to the supplied variable.The procedure can change the caller’s argument.
Function parameterA function returns a value; its parameter is not passed by reference.Use the call in an expression and do not write CALL.

14 · advanced structures

User-defined types, files, and objects

The Cambridge 9618 guide covers more than variables, arrays, and basic loops. In an exam, use the types and operations authorised by the guide for that exam year; these examples follow the 2027–2029 guide. Each construct below belongs to the curriculum specification, not to a general-purpose interpreter.

ConstructDocumented formUse and limit
EnumerationTYPE Season = (Spring, Summer, Autumn, Winter)Restricts a value to an explicit list of named alternatives.
PointerTYPE TIntPointer = ^INTEGERRepresents a reference to a memory location of the stated type; declare the variable using the type name.
RecordTYPE StudentRecord ... ENDTYPEGroups fields of different types, accessed with dot notation such as Pupil.YearGroup.
SetTYPE LetterSet = SET OF CHARGroups values of a type and can be defined with DEFINE.
Text fileOPENFILE, READFILE, WRITEFILE, EOF, CLOSEFILEReads lines sequentially; opening in WRITE creates or replaces the contents.
Random fileSEEK, GETRECORD, PUTRECORDMoves the file pointer to a record, then reads or replaces that record.
ClassCLASS, PRIVATE, PUBLIC, INHERITS, SUPERDefines properties, methods, a NEW constructor, and inheritance in the exam guide.

This example reads a text file line by line, replaces blank lines with dashes, and closes both files. It tests EOF before READFILE, so an empty file does not trigger a read that has no next line:

DECLARE LineOfText : STRING
OPENFILE "Input.txt" FOR READ
OPENFILE "Output.txt" FOR WRITE
WHILE NOT EOF("Input.txt")
    READFILE "Input.txt", LineOfText
    IF LineOfText = "" THEN
        WRITEFILE "Output.txt", "----------------------------"
    ELSE
        WRITEFILE "Output.txt", LineOfText
    ENDIF
ENDWHILE
CLOSEFILE "Input.txt"
CLOSEFILE "Output.txt"

APPEND keeps existing contents and writes after them; WRITE replaces the file. For random-access files, explain how the record address is calculated before using SEEK; PUTRECORD replaces the record at the current position. For classes, the guide uses constructor procedures named NEW and SUPER.NEW(...) to initialise the inherited part. Check the guide for the exam year, since examination examples and the syllabus have their own date ranges.

15 · versions and scope

Versions and limits

Use the 2026 guide for that exam year and the 2027–2029 guide for the corresponding assessments. Consult the official programme page for a later edition.

Cambridge pseudocode does not define a compiler, executable standard library, or compatibility with a specific language. This documentation covers assessment conventions and does not claim that Potoo IDE interprets them.
