01 · overview

What is Hedy

Hedy was created to help students begin programming with text. Instead of presenting all the syntax of a traditional language at once, the platform introduces commands and rules gradually across learning levels.

The project brings together a language, online environment, activities, and teacher materials. Commands can appear in different languages, so accepted program text depends on the selected language and level.

Status in Potoo IDE: Hedy is under evaluation. This page describes the external platform and does not imply compatibility or execution in the app.

02 · progression

Levels and gradual learning

Each level adds concepts or moves the written form closer to a language such as Python. A learner starts with small operations and can progress to variables, conditions, repetition, lists, and other features as the course advances.

The progression avoids overwhelming beginners with every punctuation rule at the start. It also means the same command can have a different form at different levels. When reading an example, always note:

  • the activity’s level;
  • the selected command language;
  • the constructs already introduced;
  • the instructions the exercise expects learners to use.

Do not compare two listings without checking these details; a syntax difference may be intentional.

03 · first commands

Output and interaction

At early levels, simple commands can display a message and ask for input. The following form illustrates introductory commands in English; other translations may be available in the platform settings:

print Welcome to Hedy!
ask What is your favorite sport?
print so your favorite sport is answer

print displays a message, ask asks a question, and answer inserts the answer in displayed text. Exact forms and available commands depend on the selected level. Use the example attached to the activity to confirm syntax in the language you chose.

04 · progressive concepts

Variables, conditions, and collections

As the course advances, Hedy introduces names for storing values, expressions, and structures that control execution. Later lessons work with conditions, repetition, and collections, bringing the code closer to conventions found in textual programming languages.

ConceptWhat learners study
VariablesStore and reuse answers and results.
ExpressionsCombine values to produce an answer.
ConditionsChoose an action based on data.
RepetitionRun instructions several times under a rule.
Lists and functionsOrganize values and reuse operations at later levels.

Content and level names are part of the platform’s curriculum. Check the current lesson because the progression may be revised.

05 · languages

Languages and command variants

Hedy supports experiences in multiple languages, including Brazilian and European Portuguese. The project maintains a translation process, and available commands can vary by translation and level.

This is different from translating only the interface: some program keywords can also be localized. When sharing an exercise:

  • state the selected language;
  • record the lesson level;
  • avoid substituting improvised translations for commands;
  • confirm that another learner can open the activity with the same settings.

If a command is not recognized, check the code language and lesson before concluding that the algorithm is wrong.

06 · worked example

Ask an interactive question

The introductory sequence can ask about a favorite sport. This English example asks about a favorite sport and includes the answer in a message:

print Welcome to Hedy!
ask What is your favorite sport?
print so your favorite sport is answer

First, run the activity and observe the input. Then change the question and observe how the answer changes. When the lesson introduces a way to store answers in a variable, write a personalized response using the command taught at that level. This progression is intentional: do not use later-level syntax before the activity introduces it.

07 · learning platform

Activities and classroom use

Alongside code, the platform organizes levels, lessons, exercises, and teacher support. Activities provide a learning path and can show feedback that helps students interpret errors. Teachers can use the materials to plan a sequence, follow a class, and contextualize the transition to Python.

To work through an activity:

  1. choose the language and level set by the course;
  2. read the explanation before editing the program;
  3. run an initial example;
  4. make a small change and observe the response;
  5. save or share work using the platform’s available options.

Account, classroom, and storage features depend on the online version and may change.

08 · study and debugging

Understanding errors

Environment feedback is part of learning. When a program does not work, first check what the lesson allows at that level and language. Then read the error message and reduce the problem to one change at a time.

  • Check whether the command was introduced at the current level.
  • Verify translated spelling and required punctuation.
  • Run the smallest version that reproduces the issue.
  • Compare supplied input with expected output.
  • When moving toward Python, note which rules are Hedy-specific and which carry over.

A syntax error can result from using a convention from another level; it does not necessarily mean the algorithmic idea is wrong.

09 · guided practice

Plan a small project across levels

A short activity can follow the platform’s progression without introducing commands before a lesson. Start with a greeting and a question in an introductory form:

print Welcome to the quiz!
ask What is 3 + 4?
print The answer is 7

This first version fixes the answer in the text. Use the activity to observe instruction order and edit a sentence. When a lesson introduces variables, store the input and use it in a message. Later, after conditions appear, compare an answer and show different feedback. Add lists or repetition only after the selected level introduces those concepts.

StageGoalNext check
MessageShow a question and a fixed answer.Change the text without changing the sequence.
InputReceive an answer with ask.Use answer after the question.
VariableStore and reuse input when the lesson teaches it.Check the value in more than one message.
DecisionChoose a response based on a condition.Test both true and false cases.
Later practiceAdd a list or repetition after its lesson.Review state after each loop pass.

This plan separates the program idea from the writing rules taught at each stage. The same activity can grow without mixing syntax from different levels.

10 · diagnosis

Common errors and what to check

Many early problems occur because a program does not match the current lesson’s conventions. Check the level and command language before changing the logic.

SymptomWhat to check
Unknown commandCheck that it has been taught at this level and that its spelling matches the selected language.
Empty or outdated answerCheck that an ask instruction ran before answer was used.
Text treated as codeCheck whether the lesson requires quotation marks and where they belong.
Block not recognizedCheck whether indentation has been introduced and whether block lines align.

Read the environment’s message alongside the highlighted code and make one change at a time. If it does not explain the cause, reduce the program to the lines that reproduce the problem. A program can be valid for another level and still fail in the current activity.

11 · transfer

What carries from Hedy to Python

Hedy helps learners build ideas that also appear in Python and other languages: running instructions in order, storing data, choosing a path, repeating operations, and breaking a task into parts. As the course progresses, compare how each concept is represented and which new conventions appear.

Do not expect a Hedy example to be a finished Python program. Levels may omit punctuation, localize commands, and reveal syntax rules gradually; Python has its own grammar from the first program. Move across in stages:

  1. describe the algorithm with words and sample input;
  2. mark which commands and values belong to the logic;
  3. look up the corresponding form in the Python material;
  4. rewrite a small block and test it before migrating the rest.

An idea such as “ask, compare, and choose a message” still applies after the written form changes. Separating the concept from the syntax makes it easier to transfer reasoning without copying commands the new language does not recognize.

12 · versions and scope

Languages, levels, and change

Hedy evolves as a platform and curriculum. The number of levels, lessons, translations, and features may change. This page avoids fixing a level count and describes the general progression in current official materials.

Syntax depends on level and language. A single example therefore does not represent the entire language. Consult the current platform and teacher manual before preparing class materials. Hedy remains under evaluation for Potoo IDE.

Syntax reference

Syntax map by level

The currently published teacher manual organizes the path into 16 levels: Basic (1–8), Advanced (9–12), and Expert (13–16). Each level accepts its own grammar. A program that works in an advanced lesson may be rejected at an early level because quotation marks, indentation, parentheses, or commands have not been introduced yet. This table summarizes the progression described by the project; the selected platform lesson is the authority for a specific activity.

LevelFeature introducedChange to recognize
1print, ask, answer, and early turtle commands.Text may appear without quotes; the reply is available as answer.
2Variables with is, pauses with sleep, and turns in degrees.The answer can be stored in a named variable.
3Lists, random selection, adding, and removing items.List items are comma-separated; randomness can change the output.
4Quotation marks around text, plus screen and color features.Literal text and variable names become visually distinct.
5Selection with if and else.Alternatives use simple one-line forms; each branch needs a command.
6elif and membership checks with in.A chain can distinguish more than two answers or check a list.
7Arithmetic, decimals, and assignment with =.Expressions can calculate with variables; a point separates decimal places.
8Repeat one line with repeat ... times.The block contains one line; repeating multiple instructions comes later.
9Indentation and multi-line blocks.Indentation shows which instructions belong to an if or repeat.
10Nested blocks and the and and or operators.Indentation shows which decision sits inside another.
11for loops over list items.The singular name represents the current item; the plural name is the collection.
12Basic functions with define and call.Defining a function does not run it; it must be called.
13Entry to Expert and a gradual shift toward Python-like syntax.Some earlier forms stop applying while the new syntax is introduced.
14Lists with brackets and repetition with for ... in range(...).Random selection and list access change form.
15Functions with def, arguments, and return.Parentheses, colons, and indentation structure the function.
16The while loop.The condition must be able to become false to avoid an endless loop.

This table describes the teacher manual consulted; earlier project materials may organize or name the sequence differently. When comparing versions, record the level and command language alongside the code.

One idea across different stages

A personalized greeting shows why syntax must be read in the context of its level:

StageRepresentative snippetWhat changed
Level 1ask What is your name?
print Hello answer		The answer uses the special name answer.
Level 2name is ask What is your name?
print Hello name		The program chooses where to store the answer.
Level 4name is ask 'What is your name?'
print 'Hello ' name		Quotes delimit text while the variable stays outside them.
Level 9if name is Hedy
    print 'Welcome back'		Indentation marks the branch body.

In the Expert path, follow the syntax shown by the lesson. For example, the documentation demonstrates a function with def, a parameter, and a return value:

def room_for(number):
    room_number = 1000 + number
    return room_number

favorite_number = 7
room_number = room_for(favorite_number)
print('Your room is ', room_number)

Diagnose errors without mixing levels

SymptomLikely checkHow to isolate it
Unknown commandThe command belongs to a later level or another code language.Check the level, code language, and spelling shown in the lesson.
A variable appears as literal textText and variables are not yet separated by that level's punctuation.Compare the lesson example and move the variable outside quotes when required.
Only one line repeatsThe level allows only one instruction in a repeat.Use the level that introduces indented blocks before grouping lines.
The wrong branch runsThe equality test may confuse the variable name with the value being checked.Read the condition left to right and use distinct test and data values.
The program does not stopA while loop does not change the state used by its condition.Record the condition before and after each iteration and add an update that can reach the stopping state.

For classroom work, keep a copy of the code from each stage. The grammar change is part of the curriculum; comparing versions side by side makes the transition to Python explicit instead of treating an earlier form as an error.
