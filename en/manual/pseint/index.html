01 · Overview

About PSeInt

PSeInt is an educational environment for writing and running algorithms in pseudocode. Its official reference describes Spanish-language instructions and profiles with more flexible or stricter rules.

The environment can also display algorithms as flowcharts, making sequences, decisions, and loops easier to follow alongside the instructions.

02 · Organization

Algorithm structure

The documented format places instructions between Proceso and FinProceso. Some versions and profiles also accept Algoritmo and FinAlgoritmo. Depending on the profile, statements may require semicolons or be separated by lines.

Proceso Saludo
    Definir nombre Como Caracter
    Escribir "¿Cómo te llamas?"
    Leer nombre
    Escribir "Hola, ", nombre
FinProceso

03 · Data

Variables, types, and assignment

An explicit declaration uses Definir nombre Como Tipo. Assignment evaluates the right-hand expression and stores its result in the variable on the left; the types must be compatible.

05 · Interaction

Input and output

Leer receives one or more values and assigns them to the listed variables. Escribir displays one or more expressions. Some profiles include output without a line break, such as Escribir Sin Saltar.

Escribir "Enter two numbers:"
Leer a, b
suma <- a + b
Escribir "Sum: ", suma

06 · Decisions

Conditions and selection

Si evaluates a condition; Entonces introduces the true branch and Sino the alternative. Segun selects among several cases and may include De Otro Modo.

Si nota >= 7 Entonces
    Escribir "Aprobado"
Sino
    Escribir "Keep practicing"
FinSi
Segun opcion Hacer
    1:
        Escribir "Start"
    De Otro Modo:
        Escribir "Invalid option"
FinSegun

Choosing a selection structure

StructureUse it whenFlow coverage
Si ... Entonces ... FinSiA condition decides whether a block runs.Without Sino, the false case continues after the block.
Si ... Sino ... FinSiThere are two alternatives.One of the two branches runs.
Segun ... De Otro Modo ... FinSegunA value selects among enumerated options.De Otro Modo handles values not listed.

Write conditions that produce a logical result, and test at least one value for each branch. In a multiple-choice selection, include a default case when unexpected values are possible.

07 · Repetition

Loops

Mientras checks its condition before each iteration. Repetir runs the body first and checks Hasta Que, so it executes at least once. Para walks a range and can use Con Paso.

Para i <- 1 Hasta 5 Con Paso 1 Hacer
    Escribir i
FinPara
Repetir
    Leer clave
Hasta Que clave = "fin"

Make sure the stopping condition can become true to avoid an infinite loop.

Compare the loops

FormWhen it testsPossible executionsAlgorithm responsibility
Mientras condición HacerBefore each pass.May run zero times.Change the data that controls the condition in the body.
Repetir ... Hasta Que condiciónAfter the body.Runs at least once.Ensure the stop condition can become true.
Para i <- inicio Hasta fin Con Paso pasoUses the counter range and step.A predictable number of iterations for that range and step.Choose bounds that include exactly the needed iterations.

Use Mientras to continue while a condition must hold, Repetir to validate after an initial attempt, and Para when the counter progression is known.

08 · Collections

Arrays and matrices

Dimension declares an array or matrix. Its notation and starting index depend on the active profile, so do not assume the bounds. This example has five positions numbered from 0 through 4:

Definir notas Como Real
Dimension notas[5]
Para i <- 0 Hasta 4 Hacer
    Leer notas[i]
FinPara
Escribir "First grade: ", notas[0]

A second dimension creates a matrix and requires one index per dimension. Check the size and bounds set by the profile before accessing a position. Arrays can also be passed to subprograms when their signature is supported by the profile.

09 · Reuse

Subprograms

SubProceso defines a reusable routine. If it returns a value, the header names the variable that receives the result; otherwise, it performs actions without returning one. Call it by name with arguments in parentheses. Parameters can be inputs or, when the profile supports the form, passed by reference to return changes to the caller.

SubProceso resultado <- Doble(numero)
    resultado <- numero * 2
FinSubProceso
Proceso Principal
    Escribir Doble(6)
FinProceso

Local variables stay within the routine. The reference includes recursive calls, such as a power calculation, and passing arrays as arguments. Prefer value parameters for calculations that should not change the original variable; use references only when a routine truly needs to return a modification.

A subprogram's contract

FormContractReview at the call
SubProceso resultado <- Nombre(parámetros)Calculates a value that can be used in an expression.Expected type, argument order, and a value on every path.
SubProceso Nombre(parámetros)Runs actions without producing a function result.Expected side effects and whether caller data will change.
Value parameterReceives a value for use in the calculation.Do not treat local changes as output to the caller.
Reference parameterCan return a change to the original argument when the profile accepts this form.Identify which variable will be modified.

Separate inputs from outputs. A function that calculates one value is usually easier to test than a routine that changes several global variables.

        Escribir "Keep practicing: ", media

12 · Writing variants

PSeInt configuration profiles

The selected profile groups the writing options accepted by PSeInt. The official documentation presents Estricto and Flexible as examples of these differences; the program also offers predefined profiles for institutions. The examples illustrate configurations, not a universal list of rules for every class.

AspectEstrictoFlexible
StructureProceso / FinProceso.Algoritmo / FinAlgoritmo.
Data declarationsDeclares variables with Definir and their types.Can infer types from how variables are used.
Statement separatorsThe examples use semicolons.The examples separate statements by line.
Collection traversalPara I <- ... accesses each position by index.Para Cada Elemento de Lista traverses the elements.
ConditionsUses comparisons such as Elemento > ValMayor.Also accepts descriptive forms such as Es Mayor Que and Es Par.

Option names, array limits, and other constructs depend on the profile actually selected. For class exercises, follow the profile specified by the teacher or course material.

Institutional profiles

PSeInt can provide profiles prepared for universities, faculties, and degree programs. They package the options chosen for a course in one file; availability depends on the list included with the distribution or supplied by the institution.

Create, save, and load a profile

  1. Open Configurar (“Configure”) → Opciones del Lenguaje (perfiles) (“Language Options (profiles)”).
  2. In the profile selection window, choose Personalizar (“Customize”).
  3. Adjust the options to match the conventions the class needs to use.
  4. Use the button with the floppy-disk icon to save the profile to a file; choose where to store it, add a description, and give the file a name that identifies the profile.
  5. To use a shared profile, reopen profile selection, choose Cargar (“Load”), and select the file you received.

After loading it, confirm that the profile is selected before writing or running an algorithm. Sharing the same file helps keep examples in a class under the same rules.

13 · Problem solving

Testing and tracing

Before running an algorithm, identify its inputs, expected result, and conditions that can change its path. Then try simple values whose results you can calculate independently.

  • Test a normal case and boundary values such as zero, one item, and the largest expected input.
  • At each loop, watch the condition, counter, and variables that change.
  • For arrays, verify every index falls inside the declared dimension.
  • For a function, compare its arguments with the returned value and inspect each return path.

The interpreter can trace execution step by step and compare it with a flowchart. A trace helps locate the moment a variable stops matching the expected value; it does not replace choosing useful test cases.

Trace a loop before testing larger cases

A dry-run table records the important values on each iteration. With n = 4, the running sum should change as follows:

    Definir n, i, suma Como Entero;
    Leer n;
    suma <- 0;
    Para i <- 1 Hasta n Hacer
        suma <- suma + i;
    FinPara
    Escribir suma;
FinProceso

After confirming this path, try n = 0 and n = 1. In the debugger, follow i, suma, and the exit condition; the first row that differs from the table points to the step to inspect.
