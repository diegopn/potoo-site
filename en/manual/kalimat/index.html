Kalimat

Kalimat is an Arabic-language programming language aimed at beginners. The official project describes object-oriented features, CSP-inspired concurrency, 2D graphics, and interoperability with C. Since the full grammar is in documents distributed by the project, this page presents confirmed concepts without inventing syntax examples.

01 · overview

What is Kalimat

Kalimat (كلمات, “words”) is a language that lets learners program using Arabic vocabulary and writing. The official website presents it as an option for beginners and describes its own tools and documentation. It is a language project, not merely a translation of keywords from another language.

The language of code is part of the learning experience; familiarity with the alphabet and writing direction should be considered when preparing materials and examples.

Status in Potoo IDE: Kalimat is under evaluation and is not run by the app. Check the official portal for current releases and rules.

02 · audience and goals

Who it was designed for

The project describes Kalimat as a language for beginners, including children. Arabic syntax aims to bring written code closer to a learner’s language, while libraries and language features allow programs beyond console exercises.

When studying Kalimat, separate three parts:

  • the language and its writing rules;
  • the tools needed to edit and run programs;
  • libraries that provide graphics or integration with other languages.

Availability of each component may depend on the distribution being used. Guides in the official package are the source for installing and running a current version.

03 · programming model

Object orientation and organization

Project documentation states that Kalimat provides object-oriented features. Classes and objects help group state and related operations, but details such as visibility, inheritance, and constructors should be checked in the rules document for the relevant version.

This organization can support exercises that progress from small functions to object models. A useful first step is to identify which values belong to each entity and which operations change those values before choosing a language construct.

Do not automatically transfer rules from Java, C++, or another object-oriented language. Kalimat’s model is defined by its own official documentation.

04 · concurrent execution

Concurrency in the CSP model

Kalimat also advertises a concurrency model related to CSP (Communicating Sequential Processes). Rather than treating all work as one sequence, the model allows learners to reason about processes that execute and communicate.

  • Process: an execution unit with an identifiable task.
  • Communication: data exchange or synchronization between processes using language constructs.
  • Coordination: define when each process can continue and how results are combined.

Concurrency requires attention to order and synchronization. Consult the official guide before using particular terminology or communication forms; this page does not specify CSP operators absent from the sources summarized here.

05 · libraries

2D graphics and games

The project highlights a 2D graphics library for building scenes and games. This feature connects programming concepts to visible outcomes: drawing objects, responding to events, and updating a scene.

A learning sequence can start with a window and a simple shape, then introduce movement and interaction. For each exercise, identify:

  1. which objects appear on screen;
  2. which properties change between updates;
  3. which events trigger an action;
  4. which rules keep the scene within desired bounds.

Module, function, and event names depend on the API distributed with Kalimat. Use the examples shipped with the package to confirm exact calls.

06 · interoperability

Integrating with C

The official portal also documents interoperability with C. This bridge can provide access to native code or libraries where appropriate, but it crosses type and resource-management models that need to agree.

Before calling external code, confirm:

  • how types on each side are represented;
  • who allocates and releases each resource;
  • how errors and return values are communicated;
  • which conventions and header files the tool requires.

Interoperability is an advanced topic and is not needed for first programs. A native library must be compatible with the version and platform in use.

07 · syntax and features

Finding the grammar

The project distributes language rule documents and examples with its installation files. Those documents are the appropriate source for checking keywords, punctuation, declarations, expressions, classes, processes, and graphics APIs.

Because the public page consulted does not expose a complete, stable grammar as plain text, this reference does not reconstruct a “Hello, world” example. To get a verifiable program:

  1. download a release from the official portal;
  2. open the language rules documents included in the package;
  3. run one of the provided examples first;
  4. change one part of the example and compare the result.

This avoids assigning Kalimat syntax guessed from a description written in another language.

08 · study and debugging

A learning path

Start with official examples and identify the required runtime. Then move from text output to variables, conditions, loops, and functions. Introduce objects, concurrency, graphics, or native integration only when an exercise calls for those features.

  • Keep the package version with the examples you test.
  • Change one thing at a time, especially in Arabic writing and text direction.
  • In a visual program, validate the logic before adding extra events.
  • For concurrency, test different orders and inspect synchronization points.
  • For C interoperability, begin with a minimal project example.

Materials and implementation choices can evolve; check the guides shipped with the installed version.

09 · versions and scope

What this reference covers

The features described here—Arabic-language programming, object orientation, a CSP model, 2D graphics, and C interoperability—are those advertised by the official project consulted. This page does not attempt to fix every syntax detail or claim compatibility between versions.

The official distribution includes rules and examples that should be used to verify the grammar and runtime. Kalimat remains under evaluation for Potoo IDE; nothing on this page should be read as an implemented integration.
