01 · overview

What is AP CSP pseudocode

AP CSP pseudocode is a set of conventions the College Board uses to present and discuss algorithms in the AP Computer Science Principles course and exam. The notation uses readable keywords and consistent symbols so learners can reason about logic without relying on a particular compiler.

It is an assessment notation, not a development environment or a complete executable language. The goal is to interpret logic and apply computing concepts.

Status in Potoo IDE: the notation is under evaluation as a reference. Its documentation here does not mean the app can run AP CSP pseudocode.

02 · curriculum context

Course, exam, and reference sheet

The College Board publishes a course framework and a reference sheet used with the exam. The sheet gathers conventions for expressions, Boolean operators, control instructions, lists, procedures, and robot applications.

A question may provide a fragment and ask about its output, a condition, a procedure call, or a change to a list. Reading the notation precisely matters more than memorizing the syntax of a real programming language.

The material is tied to the curriculum and exam year. Use the official document that applies to your class and assessment.

03 · values and expressions

Variables, operators, and data

An assignment associates an expression with a variable. The notation uses familiar arithmetic and relational operators and words for logical operations. Parentheses clarify the expression’s evaluation order.

ElementMeaning
←Assigns the calculated value to the variable on the left.
MODRemainder; requires an integer dividend ≥ 0 and divisor > 0.
AND, OR, NOTLogical conjunction, disjunction, and negation.
INPUT()Accepts a value from the user and returns it.
DISPLAY(...)Displays the value, followed by a space.

Do not read the sheet as a specification for a platform’s types or behavior. Its purpose is to represent algorithm steps in curriculum questions.

04 · control flow

Conditions and repetition

Conditions select instructions, while repetition executes a block more than once. Keywords are written in English, and braces delimit the visible scope of a structure.

number ← INPUT()
IF (number MOD 2 = 0)
{
    DISPLAY("even")
}
ELSE
{
    DISPLAY("odd")
}

The algorithm reads a number, calculates its remainder after division by two, and selects a message. This example assumes a nonnegative integer input, matching the sheet’s MOD requirements: dividend ≥ 0 and divisor > 0. Analyze the true and false cases separately. The official sheet also defines forms of repetition a fixed number of times and until a condition.

05 · collections

Lists and indexing

The notation uses lists to represent ordered sequences. List indices begin at 1, an important convention to remember when coming from many programming languages that start at zero.

OperationGeneral effect
list[i]Accesses the item at a given position.
APPEND(list, value)Adds an item to the end.
INSERT(list, i, value)Inserts a value at the given position.
REMOVE(list, i)Removes the item at a given position.
LENGTH(list)Returns the number of items.

Check the current sheet for exact signatures and behavior. When traversing a list, keep the index between 1 and its length.

06 · procedures

Procedures and return values

A procedure groups instructions under a name and can receive parameters. A function that produces a value uses the return form described by the reference. Calls let an algorithm reuse the same sequence and keep its main steps concise.

When reading a procedure, identify the arguments and match each one to its parameter. Then follow the call’s effects: changed values, displayed output, or a returned result.

Since this is a curriculum notation for procedures, do not assume that every function in a real library is described or that the example compiles directly as JavaScript, Python, or another language.

07 · robot applications

Robot commands

The reference includes notation for robot commands in a world with a grid, directions, and obstacles. Actions change position or orientation; conditions inspect the surroundings and can guide a decision.

CommandEffect
MOVE_FORWARD()Moves one square forward in the direction the robot is facing.
ROTATE_LEFT()Rotates 90° counterclockwise in place.
ROTATE_RIGHT()Rotates 90° clockwise in place.
CAN_MOVE(direction)Returns true if the open square one step in the relative direction is available; direction can be left, right, forward, or backward.

If MOVE_FORWARD() attempts to enter a blocked square or move beyond the grid, the robot stays in place and the program terminates.

  • Read the robot’s starting position and direction.
  • Determine which cells are blocked and which can be reached.
  • Track every movement and turn in instruction order.
  • Use sensors only for properties defined by the question.

This model is part of AP CSP content, but it does not necessarily describe a robotics language or simulator outside the exam.

08 · worked example

Traverse a list

Suppose a list contains positive numbers and the task is to count how many are even. Since indexing begins at 1, positions range from 1 through LENGTH(numbers). Write the loop and counter update according to the reference sheet.

count ← 0
index ← 1
REPEAT LENGTH(numbers) TIMES
{
    IF (numbers[index] MOD 2 = 0)
    {
        count ← count + 1
    }
    index ← index + 1
}

Before tracing the algorithm, confirm that the list does not change size while it is traversed. A table with index, current item, and count helps check the result.

09 · exam strategy

How to read questions

For an AP CSP question, follow one instruction at a time and record changes to variables and lists. Pay attention to words that define order, repetition count, and stopping conditions.

  • Do not confuse assignment with equality comparison.
  • Use list indexing that starts at 1.
  • Evaluate Boolean operators using precedence from the material.
  • In a loop, count each iteration and update state in the correct order.
  • In a procedure, substitute arguments for parameters mentally.

When two answers seem plausible, simulate the sequence in a table. This reduces off-by-one and branch-tracing errors.

10 · guided trace

Trace a loop to its stopping condition

REPEAT UNTIL checks its condition after running the block, so the body executes at least once. Follow that behavior as the algorithm adds the numbers from 1 through 4 and stops when the counter passes 4:

value ← 1
sum ← 0
REPEAT UNTIL (value > 4)
{
    sum ← sum + value
    value ← value + 1
}
DISPLAY(sum)
Passvalue at the start of the passsum after adding valuevalue after incrementStopping condition met?
1112No
2233No
3364No
44105Yes

value and sum are identifiers in the example: value holds the current amount to add, while sum accumulates the total.

On the first pass, value is 1 and sum becomes 1. The next passes leave the total at 3, 6, and 10. At the end of the fourth pass, the counter becomes 5; only then is the condition true and the loop stops. The output is 10.

When tracing an exam question, record values before and after the body as well as the condition. If the counter starts at 5, this structure still runs once. Choose a fixed-count loop when the task calls for a known number of iterations, including the possibility of none.

11 · changing collections

Insert, remove, and track indices

Inserting or removing an element changes the positions that follow it. Start with a list of three values:

scores ← [10, 20, 30]
INSERT(scores, 2, 15)
REMOVE(scores, 4)
Point in programListLength
Initial[10, 20, 30]3
After INSERT[10, 15, 20, 30]4
After REMOVE[10, 15, 20]3

After INSERT, the list is [10, 15, 20, 30]: the old second element and the later elements move one position to the right. REMOVE(scores, 4) deletes the last value and leaves [10, 15, 20]. The length increases and then returns to three.

When a question combines indexed access with a list change, update the sequence after each operation; do not keep using the old indices. During a traversal that removes the current item, the next element takes the same index. Advancing the counter at that point can skip it. Check the new length before accessing a position, and remember that list indices start at 1.

12 · abstraction

Use parameters and return values

A procedure can receive input, apply a rule, and return a value to its caller. In this example, isEven receives a number and returns the result of a Boolean expression:

PROCEDURE isEven(value)
{
    RETURN(value MOD 2 = 0)
}
answer ← isEven(8)

In the call, the argument 8 is assigned to the parameter value. The expression returns true, which becomes the value of answer. With isEven(7), the result would be false. The RETURN statement exits the procedure immediately, so code after it does not take part in that call.

To analyze a routine, separate its definition from its call: mark each argument, substitute the matching parameter, and follow the statements to the return. If a procedure does not return a value, trace its effects instead, such as list changes or displayed text.

13 · list reference

List semantics and tracing a procedure

The reference sheet defines mechanics that many questions require you to trace by hand. Indices start at 1. Assigning one list to another creates a copy; it does not create a second name for the same sequence. Insertions and removals change the length and shift indices, so update the list state before the next access.

FormEffectCheck
L ← RAssigns a copy of R to L.Changing L[i] later does not change the independent list R.
INSERT(L, i, x)Places x at i; items from i onward shift right.Length increases by 1; recalculate every later index.
APPEND(L, x)Adds x at the end.Length increases by 1; existing positions stay the same.
REMOVE(L, i)Removes the item at i; later items shift left.Length decreases by 1; the old item at i+1 moves to i.
FOR EACH x IN LVisits each value from first to last.Useful when the algorithm needs values but not indices.

The procedure below counts values strictly greater than a limit and returns the count. Visiting an item does not change the list:

PROCEDURE countAbove(values, limit)
{
    count ← 0
    FOR EACH value IN values
    {
        IF (value > limit)
        {
            count ← count + 1
        }
    }
    RETURN(count)
}

answer ← countAbove([8, 5, 9, 6], 6)
DISPLAY(answer)

The call returns 2: 8 and 9 are greater than 6; 5 and 6 are not. For each pass, record the current value and the count after the test. The comparison is strict: changing > to >= would include 6.

When tracing a question, record the list before and after every mutation, its current length, and the condition being evaluated. Indices below 1 or above LENGTH(L) cause an error and terminate the program under the reference sheet’s semantics. When traversing and removing items, account for shifting: after removing the current item, the next one occupies the same index; incrementing a manual index can skip it.

14 · versions and scope

Validity and limits

The reference sheet and course framework may be revised between school years and exams. The 2026 sheet is the basis of this page; students should confirm which material applies to their assessment.

AP CSP pseudocode is a shared teaching and exam notation, not a general-purpose programming language or API. This page does not claim execution in Potoo IDE and does not replace the official document.
