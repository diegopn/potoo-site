AP CSP Pseudocode

AP CSP pseudocode is the shared notation in College Board AP Computer Science Principles materials. It communicates algorithms for teaching and assessment; it is not intended to be a complete programming language or a format for running programs. This reference follows the 2026 exam reference sheet. The notation is under evaluation for Potoo IDE.

01 · overview

What is AP CSP pseudocode

AP CSP pseudocode is a set of conventions the College Board uses to present and discuss algorithms in the AP Computer Science Principles course and exam. The notation uses readable keywords and consistent symbols so learners can reason about logic without relying on a particular compiler.

It is an assessment notation, not a development environment or a complete executable language. The goal is to interpret logic and apply computing concepts.

Status in Potoo IDE: the notation is under evaluation as a reference. Its documentation here does not mean the app can run AP CSP pseudocode.

02 · curriculum context

Course, exam, and reference sheet

The College Board publishes a course framework and a reference sheet used with the exam. The sheet gathers conventions for expressions, Boolean operators, control instructions, lists, procedures, and robot applications.

A question may provide a fragment and ask about its output, a condition, a procedure call, or a change to a list. Reading the notation precisely matters more than memorizing the syntax of a real programming language.

The material is tied to the curriculum and exam year. Use the official document that applies to your class and assessment.

03 · values and expressions

Variables, operators, and data

An assignment associates an expression with a variable. The notation uses familiar arithmetic and relational operators and words for logical operations. Parentheses clarify the expression’s evaluation order.

ElementMeaning
←Assigns the calculated value to the variable on the left.
MODRemainder of integer division.
AND, OR, NOTLogical conjunction, disjunction, and negation.
INPUT()Represents an input value in examples.
DISPLAY(...)Shows a value to the user.

Do not read the sheet as a specification for a platform’s types or behavior. Its purpose is to represent algorithm steps in curriculum questions.

04 · control flow

Conditions and repetition

Conditions select instructions, while repetition executes a block more than once. Keywords are written in English, and braces delimit the visible scope of a structure.

number ← INPUT()
IF (number MOD 2 = 0)
{
    DISPLAY("even")
}
ELSE
{
    DISPLAY("odd")
}

The algorithm reads a number, calculates its remainder after division by two, and selects a message. Analyze the true and false cases separately. The official sheet also defines forms of repetition a fixed number of times and until a condition.

05 · collections

Lists and indexing

The notation uses lists to represent ordered sequences. List indices begin at 1, an important convention to remember when coming from many programming languages that start at zero.

OperationGeneral effect
list[i]Accesses the item at a given position.
APPEND(list, value)Adds an item to the end.
INSERT(list, i, value)Inserts a value at the given position.
REMOVE(list, i)Removes the item at a given position.
LENGTH(list)Returns the number of items.

Check the current sheet for exact signatures and behavior. When traversing a list, keep the index between 1 and its length.

06 · procedures

Procedures and return values

A procedure groups instructions under a name and can receive parameters. A function that produces a value uses the return form described by the reference. Calls let an algorithm reuse the same sequence and keep its main steps concise.

When reading a procedure, identify the arguments and match each one to its parameter. Then follow the call’s effects: changed values, displayed output, or a returned result.

Since this is a curriculum notation for procedures, do not assume that every function in a real library is described or that the example compiles directly as JavaScript, Python, or another language.

07 · robot applications

Robot commands

The reference includes notation for robot commands in a world with a grid, directions, and obstacles. Actions change position or orientation; conditions inspect the surroundings and can guide a decision.

  • Read the robot’s starting position and direction.
  • Determine which cells are blocked and which can be reached.
  • Track every movement and turn in instruction order.
  • Use sensors only for properties defined by the question.

This model is part of AP CSP content, but it does not necessarily describe a robotics language or simulator outside the exam.

08 · worked example

Traverse a list

Suppose a list contains positive numbers and the task is to count how many are even. Since indexing begins at 1, positions range from 1 through LENGTH(numbers). Write the loop and counter update according to the reference sheet.

count ← 0
index ← 1
REPEAT LENGTH(numbers) TIMES
{
    IF (numbers[index] MOD 2 = 0)
    {
        count ← count + 1
    }
    index ← index + 1
}

Before tracing the algorithm, confirm that the list does not change size while it is traversed. A table with index, current item, and count helps check the result.

09 · exam strategy

How to read questions

For an AP CSP question, follow one instruction at a time and record changes to variables and lists. Pay attention to words that define order, repetition count, and stopping conditions.

  • Do not confuse assignment with equality comparison.
  • Use list indexing that starts at 1.
  • Evaluate Boolean operators using precedence from the material.
  • In a loop, count each iteration and update state in the correct order.
  • In a procedure, substitute arguments for parameters mentally.

When two answers seem plausible, simulate the sequence in a table. This reduces off-by-one and branch-tracing errors.

10 · versions and scope

Validity and limits

The reference sheet and course framework may be revised between school years and exams. The 2026 sheet is the basis of this page; students should confirm which material applies to their assessment.

AP CSP pseudocode is a shared teaching and exam notation, not a general-purpose programming language or API. This page does not claim execution in Potoo IDE and does not replace the official document.
