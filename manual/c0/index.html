01 · visão geral

O que é C0

C0 foi projetada para ensinar programação imperativa e estruturas de dados com uma linguagem familiar a quem já viu C, mas com um conjunto menor de recursos e regras mais controladas. Ela aparece em disciplinas introdutórias da Carnegie Mellon University, incluindo materiais do curso 15-122.

O objetivo didático é deixar explícitos os tipos, o fluxo de controle, a memória e as condições que uma função precisa respeitar. O curso descreve C0 como um subconjunto seguro de C, com coleta automática de memória, inteiros de intervalo fixo e contratos. A linguagem especifica seu comportamento para que estudantes não dependam de casos indefinidos de C. Ela não pretende aceitar todo programa C: um arquivo escrito para C pode depender de recursos que não existem em C0.

Estado no Potoo IDE: C0 está em avaliação. O ambiente e os compiladores da Carnegie Mellon são as referências para executar os exemplos desta página.

02 · contexto

Origem e objetivos de ensino

C0 foi desenvolvida para acompanhar o ensino de programação e raciocínio sobre memória. Sua sintaxe se aproxima de uma linguagem da família C, enquanto seu projeto restringe construções que dificultariam a análise do comportamento de um programa iniciante.

A referência oficial organiza a linguagem em torno de funções, tipos, comandos e contratos. Os cursos usam esses recursos para desenvolver soluções corretas e explicar por que uma função funciona, em vez de apenas obter uma saída em um caso específico.

  • Aprendizagem imperativa: variáveis, atribuições, chamadas, condições e laços.
  • Abstração: funções e estruturas nomeiam operações e dados relacionados.
  • Raciocínio sobre correção: pré-condições, pós-condições e invariantes registram o que precisa valer.

03 · dados e tipos

Tipos, valores e coleções

C0 define valores e operações de forma precisa para que programas não dependam dos casos indefinidos de C. As regras de int, texto, vetores e estruturas são parte da linguagem; não devem ser inferidas de um compilador C comum.

Tipo ou formaO que representaRegra para lembrar
intPalavra inteira de 32 bits em complemento de dois.Operações aritméticas são módulo 232; valores passam do maior para o menor representável.
boolUm dos valores true e false.Condições e contratos precisam produzir um booleano; && e || têm curto-circuito.
charCaractere ASCII, não Unicode.Comparações seguem o código ASCII; literais usam aspas simples.
stringTexto constante composto de caracteres ASCII.\0 não pode aparecer em um literal; compare por funções da biblioteca, não com ==.
t[]Referência para um vetor alocado de valores do tipo t.Crie com alloc_array(t, n); índices válidos são 0 a n-1.
t*Ponteiro para um valor t em memória; inclui NULL.alloc(t) cria a posição; verificar p != NULL antes de *p evita uma falha por ponteiro nulo.
struct sRegistro nomeado com campos possivelmente de tipos diferentes.É alocado em memória e usado por ponteiro, como p->field; não é copiado por valor como um int.
voidTipo de retorno para função sem resultado.Use apenas em funções chamadas como instruções.

Os vetores são referências pequenas para uma área de comprimento fixo. O acesso fora dos limites — índice negativo ou maior ou igual ao comprimento — provoca uma violação de limites e encerra o programa. A coleta automática de memória cuida de vetores e estruturas que deixam de ser alcançáveis; o programa não chama free. Isso elimina a liberação manual, mas não torna todo acesso seguro: limites, valores nulos e relações entre campos ainda precisam ser raciocinados.

O inteiro é modular, não um número de precisão ilimitada: por exemplo, aumentar o maior int representável faz o resultado voltar ao menor valor. Divisão inteira trunca em direção a zero; dividir por zero e o caso especial -2^31 / -1 causam erro aritmético. Se um exercício exige uma faixa menor, declare-a no contrato e confira antes de calcular.

04 · organização

Funções, declarações e blocos

Um programa é organizado em funções. A assinatura declara o tipo do resultado, o nome da função e os tipos dos parâmetros; o corpo fica entre chaves. Declarações locais introduzem valores usados no bloco, e return encerra uma função produzindo o resultado esperado.

int square(int value) {
    return value * value;
}

int main() {
    int result = square(6);
    return 0;
}

O exemplo mostra uma função pura pequena e uma função de entrada convencional. A biblioteca e o contrato exigido para main podem depender do contexto de compilação do curso. Comentários no código devem explicar propósito ou uma decisão relevante, sem substituir uma descrição precisa dos parâmetros e do resultado.

05 · fluxo

Decisões, repetições e chamadas

C0 oferece os comandos usuais de um modelo imperativo: sequência, seleção, repetição, chamada de função e retorno. As condições são expressões booleanas. Um laço deve avançar em direção à condição de saída; a prova informal dessa propriedade evita execuções que não terminam.

ConstruçãoFunção
if / elseEscolhe um bloco a partir de uma condição.
whileRepete enquanto a condição permanecer verdadeira.
forReúne inicialização, condição e atualização em um laço contado.
returnDevolve o valor declarado pela assinatura da função.

Vetores, estruturas e ponteiros permitem representar coleções e relações entre dados. Cada acesso a vetor precisa permanecer dentro dos limites válidos; sair deles é uma violação de segurança. Use contratos e invariantes para justificar índices e relações entre dados, e não pressuponha o comportamento de uma implementação C diferente.

06 · correção

Contratos, invariantes e segurança

Contratos registram as condições sob as quais uma função pode ser chamada e o que ela garante ao terminar. Uma pré-condição descreve uma exigência de entrada; uma pós-condição descreve o resultado. Um invariante de laço resume uma propriedade que deve continuar verdadeira a cada repetição.

  • Pré-condição: indique limites e relações que os argumentos precisam satisfazer.
  • Pós-condição: relacione o valor retornado ao problema que a função resolve.
  • Invariante: explique o significado do estado mantido durante um algoritmo iterativo.
AnotaçãoO que especificaVerificação dinâmica
//@requiresCondição que os argumentos devem satisfazer.Antes do corpo da função.
//@ensuresPropriedade do resultado; pode usar \result.Antes do retorno da função.
//@loop_invariantPropriedade que deve valer durante o laço.Em cada iteração, antes do teste de saída.

A referência escreve pré-condições e pós-condições em comentários especiais, por exemplo //@requires expressão; e //@ensures expressão;. Em uma pós-condição, \result representa o valor devolvido. Invariantes de laço usam //@loop_invariant expressão; e precisam expressar um valor lógico. Quando a verificação dinâmica está habilitada, as ferramentas avaliam esses contratos nos pontos definidos pela referência; contratos e provas de limites continuam sendo responsabilidade de quem escreve o programa.

int maximum(int x, int y)
//@ensures \result >= x && \result >= y;
{
    if (x > y) {
        return x;
    } else {
        return y;
    }
}

07 · exemplo guiado

Planejar uma função de busca

Considere uma função que procura um inteiro em um vetor. Antes da implementação, registre o que significa “encontrar”: devolver um índice válido quando o valor aparece e comunicar a ausência quando não aparece. O tipo e o valor usado para representar “não encontrado” devem seguir a convenção do exercício.

  1. Declare os argumentos do vetor, do tamanho e do valor procurado.
  2. Defina se o tamanho pode ser zero e qual condição o vetor precisa satisfazer.
  3. Percorra índices válidos em ordem, verificando cada elemento.
  4. Retorne o índice assim que a igualdade for encontrada.
  5. Depois do laço, devolva o marcador de ausência documentado.

Um contrato de saída pode relacionar o índice devolvido ao elemento correspondente. Se o resultado indicar ausência, a pós-condição deve dizer que nenhum elemento do intervalo satisfaz a busca. Assim, a especificação cobre também vetores vazios e valores repetidos.

08 · estudo e depuração

Como estudar e depurar C0

Compile pequenos trechos enquanto aprende. Para cada função, anote a assinatura, os casos de entrada e o significado esperado do resultado. Depois acompanhe manualmente a execução com uma tabela de variáveis; em algoritmos sobre coleções, inclua o índice e o intervalo já processado.

  • Teste valores de fronteira: zero, tamanho mínimo, primeiro e último índice.
  • Exercite caminhos verdadeiro e falso em cada condição.
  • Inclua vetores vazios, de um elemento e com valores repetidos quando o contrato permitir.
  • Leia a mensagem do verificador ou compilador e compare-a com a pré-condição e o invariante relevantes.

Um programa que compila ainda pode resolver o problema errado. Compare a saída com um cálculo independente e teste casos que exercitem todos os ramos.

09 · percurso guiado

Vetores, contratos e segurança da memória

Uma função que percorre um vetor precisa relacionar três fatos: o comprimento armazenado na referência, o índice atual e a quantidade de elementos já processada. O exemplo soma um prefixo de tamanho n:

int sum_prefix(int[] values, int n)
//@requires 0 <= n && n <= \length(values);
{
    int i = 0;
    int total = 0;
    while (i < n)
    //@loop_invariant 0 <= i && i <= n;
    {
        total = total + values[i];
        i = i + 1;
    }
    return total;
}

Para values = [4, 2, 5] e n = 3, os pares (i, total) após cada passagem são (1, 4), (2, 6) e (3, 11). Quando n vale zero, o corpo não acessa o vetor e a função retorna zero. A pré-condição garante que n não exceda o comprimento; a condição i < n mantém cada índice acessado dentro do prefixo. O invariante escrito protege o limite do índice, mas não afirma por si só que total é a soma do prefixo — essa relação deve fazer parte da explicação de correção.

OperaçãoGarantia que deve ser estabelecidaViolação observável
alloc_array(t, n)n >= 0; os acessos usam 0 <= i < n.Índice fora do vetor encerra o programa.
alloc(t)Depois da alocação, inicialize os campos antes de depender deles; um ponteiro pode ser NULL.Desreferenciar NULL encerra o programa.
p->fieldp != NULL e o campo pertence à estrutura declarada.Acesso através de ponteiro nulo termina com exceção de execução.
//@requiresPrecondição verdadeira antes do corpo, como limite de vetor.Com a checagem dinâmica habilitada, a chamada incorreta falha antes do corpo.
//@ensures e //@loop_invariantPós-condição descreve o retorno; invariante descreve o estado no ponto do laço.Com a checagem dinâmica habilitada, a propriedade falsa é detectada nos pontos definidos pela referência.
assert(e);Condição interna que deve ser verdadeira naquele ponto.A instrução sempre executa; se e for falso, a execução é abortada.

Os contratos de função são comentários especiais posicionados junto à assinatura. //@requires especifica o que o chamador precisa garantir; //@ensures pode usar \result para falar do retorno. \length(A) só é permitido em contratos. Um invariante de laço é verificado a cada iteração imediatamente antes de testar a condição de saída, quando a verificação dinâmica está habilitada. Anotações de contrato podem não ser verificadas por uma compilação comum: use as opções das ferramentas da disciplina e leia as mensagens de falha. Já a instrução de execução assert(e); é sempre avaliada.

Um ponteiro precisa de um argumento adicional sobre a existência do objeto. Considere uma lista ligada: toda leitura de campo deve ocorrer depois do teste contra NULL. Estruturas são grandes valores alocados e normalmente circulam como ponteiros; os campos iniciam com os valores padrão de seus tipos quando a estrutura é alocada. A coleta automática dispensa free, mas não corrige a lógica de um campo não inicializado para a tarefa, uma referência nula ou uma estrutura sem o invariante que o algoritmo pressupõe.

struct node {
    int value;
    struct node* next;
};

struct node* first = alloc(struct node);
first->value = 7;
first->next = NULL;
if (first->next != NULL) {
    int next_value = first->next->value;
}

Ao depurar, teste separadamente vetor vazio, um elemento, o último índice válido, e a primeira posição inválida. Para ponteiros, teste tanto o caso nulo quanto um objeto alocado; para aritmética, use valores perto dos extremos de 32 bits. O compilador pode detectar inconsistências de tipo, enquanto as checagens de contrato e as tabelas de execução ajudam a localizar violações de pré-condições, limites e invariantes.

10 · versão e escopo

Escopo desta referência

A referência oficial da CMU listada aqui é C0.14, revisão 707, de 18 de fevereiro de 2025. Ela separa a linguagem-base da extensão C1, que reúne recursos experimentais habilitados em arquivos .c1. Esta página descreve a linguagem-base C0; confira a versão adotada pela disciplina.

Esta página se limita às ideias introdutórias compartilhadas pelas referências consultadas. Não presume suporte de C0 no Potoo IDE, nem substitui o manual da versão usada em sala. A linguagem permanece em avaliação como candidata do projeto.
