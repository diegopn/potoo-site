01 · panorama

Qué es Robot Karol

Robot Karol enseña programación mediante acciones de un robot en un mundo cuadriculado. En lugar de comenzar con una pantalla vacía y muchos conceptos abstractos, el alumnado observa el movimiento, la orientación y los obstáculos después de cada instrucción.

El proyecto en línea actual conserva este enfoque didáctico y ofrece tareas, representación visual y edición por bloques o texto. Los materiales pueden incluir formas de código y niveles distintos; utiliza la documentación correspondiente a cada actividad.

Estado en Potoo IDE: Robot Karol está en evaluación. Es distinto de Karel the Robot; la aplicación no ofrece una integración.

02 · mundo de ejecución

El mundo cuadriculado

El robot ocupa una celda y tiene una orientación. El escenario de una tarea define el espacio, los obstáculos y, cuando corresponde, las marcas o metas. Una instrucción modifica el estado del mundo: el robot avanza, gira o interactúa con elementos disponibles.

ComponenteFunción en el ejercicio
RobotEjecuta instrucciones y mantiene posición y orientación.
CuadrículaDefine las posiciones por las que se puede mover.
ObstáculosRestringen el movimiento y motivan el uso de sensores.
Marcas u objetosPueden representar elementos que el robot encuentra o modifica.
Escenario objetivoDescribe el estado que debe alcanzar la solución.

Lee las condiciones iniciales antes de programar. El mismo algoritmo puede fallar si cambia la orientación inicial o la posición de un obstáculo.

03 · acciones

Comandos y sensores

Las acciones básicas cambian la posición u orientación del robot. Las condiciones observan el entorno para que un programa responda al escenario. En el modo textual propio, una secuencia puede utilizar comandos en alemán:

Schritt
LinksDrehen

El fragmento avanza una casilla y gira a la izquierda. Estos comandos también corresponden a bloques del editor visual; los modos de Python y Java son materiales didácticos separados.

  • Acciones: avanzar, girar e interactuar con objetos previstos en la tarea.
  • Condiciones: verificar el camino libre, los obstáculos o los elementos de la celda actual.
  • Observación: consultar el estado del mundo antes de decidir el siguiente paso.

Vocabulario del modo textual

El proyecto documenta comandos en alemán. Aparecen en su propio modo textual y corresponden a bloques del editor visual. El repositorio resume las instrucciones principales así:

ComandoEfecto documentado
Schritt / Schritt(anzahl)Avanza una casilla o la cantidad indicada.
LinksDrehen / RechtsDrehenGira 90 grados a la izquierda o a la derecha; el modo textual admite una cantidad opcional.
Hinlegen / Hinlegen(anzahl)Coloca un ladrillo o la cantidad indicada delante.
Aufheben / Aufheben(anzahl)Recoge un ladrillo o la cantidad indicada delante.
MarkeSetzen / MarkeLöschenMarca la casilla actual o elimina su marca.
BeendenDetiene el programa en ese punto.

Estos nombres pertenecen a la notación propia de Robot Karol y conservan la grafía alemana. En cambio, karol.schritt() es una llamada de Python que aparece en el curso asociado. Son sintaxis distintas; comprueba el modo de código activo antes de copiar un ejemplo.

04 · flujo de control

Secuencia, bucles y condiciones

El entorno enseña a construir programas con secuencias, repeticiones y decisiones condicionales. Algunos materiales incluyen repetición una cantidad fija de veces y repetición controlada por sensores.

IdeaPregunta útil
Secuencia¿Qué acción debe ocurrir primero?
Repetición contada¿Cuántos pasos o giros hacen falta?
Repetición condicional¿Qué sensor indica que se debe continuar o detener?
Decisión¿Qué hacer cuando el camino está libre o bloqueado?
Procedimiento¿Qué secuencia debe tener un nombre para reutilizarse?

Las condiciones basadas en sensores hacen que el algoritmo se adapte a escenarios relacionados. Aun así, prueba todos los casos del ejercicio y asegúrate de que cada bucle pueda terminar.

Formas textuales de repetición y decisión

El repositorio documenta repetición contada, repetición condicionada, repetición continua y decisiones con o sin alternativa. En el modo textual, palabras propias delimitan cada bloque:

wiederhole 4 mal
  Schritt
endewiederhole

wenn IstWand dann
  LinksDrehen
sonst
  Schritt
endewenn

Usa repetición contada cuando conoces la cantidad de acciones. Elige una condición cuando la tarea depende del mundo, por ejemplo continuar hasta encontrar una pared. Un bucle infinito necesita una forma clara de terminar, como una orden de parada o una condición externa.

Sensores y decisiones

El modo textual incluye consultas sobre paredes, ladrillos, marcas y orientación del robot. Hay formas afirmativas y negativas, y algunas consultas aceptan una cantidad esperada de ladrillos. Antes de combinar sensores, determina si la consulta se refiere a la casilla actual, a la casilla de delante o a una dirección absoluta; esa diferencia cambia la decisión del programa.

Consulta rápida de las formas de control

05 · modos de edición

Bloques, texto y actividades

El proyecto en línea ofrece edición visual por bloques y edición textual. Los bloques hacen visible la estructura de condiciones y bucles; el texto permite estudiar comandos y puede preparar el paso a los lenguajes de programación.

La plataforma también organiza tareas y materiales de curso. Para trabajar con una actividad:

  1. lee el objetivo y examina el estado inicial del mundo;
  2. escribe una estrategia antes de colocar bloques;
  3. ejecuta el programa y observa dónde se desvía el robot de la meta;
  4. corrige la parte mínima necesaria y vuelve a probar.

Algunos cursos acompañan las actividades con Python o Java. Esos modos forman parte de materiales específicos y no deben confundirse con la representación propia de Robot Karol.

Instrucciones reutilizables y flujo del editor

Una instrucción propia da nombre a un conjunto de comandos para reutilizarlo en distintas partes de la solución. El repositorio documenta definiciones delimitadas por Anweisung y endeAnweisung. Así se pueden nombrar operaciones como cruzar un pasillo, construir un lado o regresar al punto inicial.

En tareas con varios bloques, se ejecuta el bloque designado como programa principal. Los bloques auxiliares quedan inactivos hasta que se llaman. En texto, un programa continuo puede ejecutarse sin la estructura visual de bloques. La documentación también describe comentarios con // y formas antiguas con asterisco; sigue la sintaxis del material del curso.

El editor de tareas permite que el docente prepare mundos y objetivos propios para compartirlos mediante un enlace o archivo. Una actividad útil especifica posición y dirección iniciales, obstáculos, objetos disponibles y estado final esperado.

06 · ejemplo guiado

Recorrer una fila despejada

Supón que una tarea pide al robot avanzar por un pasillo de longitud conocida. En el modo textual propio, la forma documentada de repetición puede ejecutar cuatro veces el comando de avanzar; en el editor de bloques, utiliza el bloque equivalente.

wiederhole 4 mal
    Schritt
endewiederhole

Antes de ejecutarlo, confirma que el pasillo tenga al menos cuatro celdas libres y que el robot esté orientado hacia él. Después prueba un pasillo más corto o con un obstáculo para entender por qué se necesita un sensor cuando no se conoce la longitud de antemano.

Ejercicios progresivos

Resuelve estas tareas en el modo textual propio o con los bloques equivalentes. En cada etapa, anota el estado inicial, el estado objetivo y la prueba que confirma la solución antes de generalizar:

EtapaTareaComprobación
1 · secuenciaAvanza por un pasillo vacío de longitud fija.Comprueba la cantidad y la orientación tras el último paso.
2 · repeticiónConstruye un cuadrado con ladrillos o recorre sus cuatro lados.Compara posición, orientación y objetos con el estado inicial.
3 · decisiónGira o avanza según haya una pared delante.Ejecuta un escenario despejado y otro bloqueado.
4 · procedimientoAsigna un nombre a una acción compuesta y reutilízala en otra parte de la ruta.Cambia una instrucción auxiliar y comprueba todas sus llamadas.
5 · generalizaciónRepite la tarea en un mundo personalizado con otra posición inicial.Separa las hipótesis garantizadas de las que requieren sensores.

07 · planificación

Planificar y depurar tareas

Los problemas con robots son buenos ejercicios de descomposición. Da nombre a las acciones repetidas, identifica decisiones con sensores y dibuja la ruta en una cuadrícula. La ejecución visual ayuda a localizar el paso en el que la orientación o la posición dejan de ser las esperadas.

  • Prueba exactamente el escenario inicial descrito.
  • Observa la orientación después de cada giro.
  • Comprueba si los sensores se refieren a la orientación actual del robot.
  • Prueba casos límite, como el pasillo más corto y un obstáculo justo delante.
  • Si la solución usa Python o Java, consulta la semántica de esa integración en el material correspondiente.

El objetivo es que la secuencia funcione bajo las condiciones del ejercicio, no solo en el primer escenario probado.

Casos de prueba para un mundo en cuadrícula

Una tarea puede parecer resuelta en un escenario y fallar si cambia la distancia o la posición inicial. Separa el algoritmo de la configuración concreta: anota las suposiciones de la solución y comprueba que el enunciado las garantice.

  • Prueba el pasillo válido más corto y el más largo previsto por la tarea.
  • Coloca una pared inmediatamente delante para comprobar la respuesta del sensor.
  • Prueba ambos resultados de cada condición, incluida la ausencia de una marca o un ladrillo.
  • Después de un giro, confirma la orientación antes de interpretar una consulta direccional.
  • Vuelve a ejecutar la tarea después de cambiar el orden de los comandos de una instrucción auxiliar.

Si el robot se detiene antes de la meta, compara su estado tras cada comando: casilla, orientación y objetos modificados. El recorrido suele mostrar si el error está en la ruta, en el límite de una repetición o en la condición de parada.

08 · proyectos relacionados

Robot Karol y Karel the Robot

Robot Karol y Karel the Robot comparten la idea didáctica de controlar un robot, pero son proyectos y ecosistemas distintos. La referencia de Karel de este sitio sigue un modelo Java de Stanford; Robot Karol tiene su propio entorno alemán, plataforma en línea y materiales didácticos.

Los comandos, sensores, la sintaxis y el comportamiento no son intercambiables. No presentes código de una implementación de Karel como código de Robot Karol sin adaptarlo y probarlo.

09 · versiones y alcance

Versiones y soporte

Esta referencia sigue la plataforma en línea y su repositorio público. Las funciones de interfaz, los modos de texto, las tareas y las API de curso pueden evolucionar; utiliza el tutorial y los ejemplos de la versión activa para confirmar los comandos.

El manual describe el entorno original. No significa que Potoo IDE incluya el simulador, el robot o las herramientas del proyecto. Robot Karol sigue en evaluación.
