01 · panorama

Qué es el pseudocódigo AP CSP

El pseudocódigo AP CSP es un conjunto de convenciones que utiliza el College Board para presentar y analizar algoritmos en el curso y examen de AP Computer Science Principles. La notación utiliza palabras clave legibles y símbolos coherentes para razonar sobre la lógica sin depender de un compilador específico.

Es una notación de evaluación, no un entorno de desarrollo ni un lenguaje ejecutable completo. El objetivo es interpretar la lógica y aplicar conceptos de informática.

Estado en Potoo IDE: la notación está en evaluación como referencia. Documentarla aquí no significa que la aplicación pueda ejecutar pseudocódigo AP CSP.

02 · contexto curricular

Curso, examen y hoja de referencia

El College Board publica un marco curricular y una hoja de referencia que acompaña el examen. La hoja reúne convenciones para expresiones, operadores booleanos, instrucciones de control, listas, procedimientos y aplicaciones con robots.

Una pregunta puede proporcionar un fragmento y pedir su salida, el valor de una condición, una llamada a procedimiento o un cambio en una lista. Leer la notación con precisión es más importante que memorizar la sintaxis de un lenguaje de programación real.

El material está ligado al currículo y al año de examen. Para preparar una evaluación, utiliza el documento oficial correspondiente a tu curso.

03 · valores y expresiones

Variables, operadores y datos

Una asignación relaciona una expresión con una variable. La notación utiliza operadores aritméticos y relacionales habituales y palabras para las operaciones lógicas. Los paréntesis aclaran el orden en que se evalúa una expresión.

ElementoSignificado
←Asigna el valor calculado a la variable de la izquierda.
MODResto; requiere dividendo entero ≥ 0 y divisor entero > 0.
AND, OR, NOTConjunción, disyunción y negación lógica.
INPUT()Recibe y devuelve un valor introducido por el usuario.
DISPLAY(...)Muestra el valor y añade un espacio.

No interpretes la hoja como una especificación de tipos o del comportamiento de una plataforma. Su objetivo es representar pasos algorítmicos en preguntas curriculares.

04 · flujo de control

Condiciones y repeticiones

Las condiciones seleccionan instrucciones y las repeticiones ejecutan un bloque más de una vez. Las palabras clave están en inglés y las llaves delimitan visualmente el ámbito de cada estructura.

number ← INPUT()
IF (number MOD 2 = 0)
{
    DISPLAY("even")
}
ELSE
{
    DISPLAY("odd")
}

El algoritmo lee un número, calcula el resto de dividirlo entre dos y elige un mensaje. El ejemplo presupone una entrada entera no negativa, según las restricciones de MOD: dividendo ≥ 0 y divisor > 0. Analiza por separado los casos verdadero y falso. La hoja oficial también define formas de repetir una cantidad fija de veces y hasta que ocurra una condición.

05 · colecciones

Listas e índices

La notación utiliza listas para representar secuencias ordenadas. Los índices de las listas comienzan en 1, una convención importante para quienes vienen de muchos lenguajes que empiezan a contar desde cero.

OperaciónEfecto general
list[i]Accede al elemento en la posición indicada.
APPEND(list, value)Añade un elemento al final.
INSERT(list, i, value)Inserta un valor en la posición indicada.
REMOVE(list, i)Elimina el elemento de una posición.
LENGTH(list)Devuelve la cantidad de elementos.

Consulta la hoja vigente para confirmar las firmas y el comportamiento exactos. Al recorrer una lista, mantén el índice entre 1 y su longitud.

06 · procedimientos

Procedimientos y valores de retorno

Un procedimiento agrupa instrucciones bajo un nombre y puede recibir parámetros. Una función que devuelve un resultado utiliza la forma de retorno descrita en la referencia. Las llamadas permiten reutilizar una secuencia y mantener concisos los pasos principales del algoritmo.

Al leer un procedimiento, identifica los argumentos y relaciónalos con sus parámetros. Después sigue los efectos de la llamada: valores modificados, salida mostrada o resultado devuelto.

Como esta notación de procedimientos pertenece al currículo, no presupongas que documenta todas las funciones de una biblioteca real o que un ejemplo se ejecuta directamente en JavaScript, Python u otro lenguaje.

07 · aplicaciones con robots

Comandos de robot

La referencia incluye notación para controlar un robot en un mundo con cuadrícula, direcciones y obstáculos. Las acciones modifican la posición o la orientación; las condiciones observan el entorno y pueden guiar una decisión.

ComandoEfecto
MOVE_FORWARD()Avanza una casilla en la dirección hacia la que mira el robot.
ROTATE_LEFT()Gira 90° en sentido antihorario sin cambiar de casilla.
ROTATE_RIGHT()Gira 90° en sentido horario sin cambiar de casilla.
CAN_MOVE(direction)Devuelve true si la casilla abierta en esa dirección relativa está disponible; direction puede ser left, right, forward o backward.

Si MOVE_FORWARD() intenta entrar en una casilla bloqueada o salir de la cuadrícula, el robot permanece en su posición y el programa termina.

  • Lee la posición y la orientación iniciales del robot.
  • Determina qué celdas están bloqueadas y cuáles son accesibles.
  • Sigue cada movimiento y giro en el orden de las instrucciones.
  • Utiliza sensores solo para las propiedades que defina el ejercicio.

Este modelo forma parte del contenido de AP CSP, pero no describe necesariamente un lenguaje o simulador de robótica externo al examen.

08 · ejemplo guiado

Recorrer una lista

Imagina una lista de números positivos y la tarea de contar cuántos son pares. Como los índices empiezan en 1, las posiciones van de 1 a LENGTH(numbers). Escribe el bucle y la actualización del contador según la hoja de referencia.

count ← 0
index ← 1
REPEAT LENGTH(numbers) TIMES
{
    IF (numbers[index] MOD 2 = 0)
    {
        count ← count + 1
    }
    index ← index + 1
}

Antes de seguir el algoritmo, confirma que la lista no cambie de tamaño durante el recorrido. Una tabla con index, el elemento actual y count ayuda a verificar el resultado.

09 · estrategia de examen

Cómo interpretar preguntas

En una pregunta de AP CSP, sigue una instrucción cada vez y anota los cambios en variables y listas. Presta atención a las palabras que definen el orden, la cantidad de repeticiones y las condiciones de parada.

  • No confundas asignación con comparación de igualdad.
  • Utiliza índices de listas que empiezan en 1.
  • Evalúa los operadores booleanos según la precedencia indicada en el material.
  • En un bucle, cuenta cada iteración y actualiza el estado en el orden correcto.
  • En un procedimiento, sustituye mentalmente cada parámetro por su argumento.

Si dos respuestas parecen posibles, simula la secuencia en una tabla. Así reduces errores de índice y de seguimiento de ramas.

10 · práctica guiada

Seguir un bucle hasta la condición de salida

REPEAT UNTIL comprueba la condición después de ejecutar el bloque. Por eso, el cuerpo se ejecuta al menos una vez. Sigue este comportamiento al sumar del 1 al 4 y detenerse cuando el contador supere 4:

value ← 1
sum ← 0
REPEAT UNTIL (value > 4)
{
    sum ← sum + value
    value ← value + 1
}
DISPLAY(sum)
Pasadavalue al iniciosum tras sumarvalue tras actualizar¿Termina?
1112No
2233No
3364No
44105Sí

En la primera pasada, value vale 1 y sum pasa a 1. Las siguientes dejan el total en 3, 6 y 10. Al final de la cuarta, el contador recibe 5; solo entonces la condición es verdadera y termina el bucle. La salida es 10.

Al seguir una pregunta, registra los valores antes y después del cuerpo y también la condición. Si el contador empieza en 5, esta estructura aun así se ejecuta una vez. Utiliza un bucle de cantidad fija cuando la tarea pida un número conocido de iteraciones, incluso si puede ser cero.

11 · colecciones cambiantes

Insertar, eliminar y seguir los índices

Insertar o eliminar un elemento modifica las posiciones que vienen después. Empieza con una lista de tres valores:

scores ← [10, 20, 30]
INSERT(scores, 2, 15)
REMOVE(scores, 4)
MomentoListaLongitud
Inicial[10, 20, 30]3
Después de INSERT[10, 15, 20, 30]4
Después de REMOVE[10, 15, 20]3

Después de INSERT, la lista queda como [10, 15, 20, 30]: el antiguo segundo elemento y los siguientes avanzan una posición. REMOVE(scores, 4) elimina el último valor y deja [10, 15, 20]. La longitud primero aumenta y luego vuelve a tres.

Cuando una pregunta combina acceso por índice y cambios en la lista, actualiza la secuencia tras cada operación; no conserves los índices anteriores. Si durante el recorrido se elimina el elemento actual, el siguiente ocupa ese mismo índice. Avanzar el contador en ese momento puede saltarlo. Comprueba la longitud actual antes de acceder a una posición y recuerda que los índices empiezan en 1.

12 · abstracción

Usar parámetros y valores de retorno

Un procedimiento puede recibir una entrada, aplicar una regla y devolver un valor a quien lo llamó. En este ejemplo, isEven recibe un número y devuelve el resultado de una expresión booleana:

PROCEDURE isEven(value)
{
    RETURN(value MOD 2 = 0)
}
answer ← isEven(8)

En la llamada, el argumento 8 se asigna al parámetro value. La expresión devuelve true, que pasa a ser el valor de answer. Con isEven(7), el resultado sería false. La instrucción RETURN sale del procedimiento de inmediato; el código que venga después no participa en esa llamada.

Para analizar una rutina, separa su definición de la llamada: anota cada argumento, sustitúyelo por el parámetro correspondiente y sigue las instrucciones hasta el retorno. Si un procedimiento no devuelve un valor, sigue sus efectos, como cambios en una lista o el texto mostrado.

13 · consulta de listas

Semántica de listas y seguimiento de un procedimiento

La hoja de referencia define operaciones que muchas preguntas requieren trazar a mano. Los índices empiezan en 1. Asignar una lista a otra crea una copia; no crea un segundo nombre para la misma secuencia. Las inserciones y eliminaciones cambian la longitud y desplazan los índices, así que actualiza el estado de la lista antes del siguiente acceso.

FormaEfectoComprobación
L ← RAsigna una copia de R a L.Modificar L[i] después no modifica la lista independiente R.
INSERT(L, i, x)Coloca x en i; los elementos desde i se desplazan a la derecha.La longitud aumenta en 1; vuelve a calcular los índices posteriores.
APPEND(L, x)Añade x al final.La longitud aumenta en 1; las posiciones existentes no cambian.
REMOVE(L, i)Elimina el elemento de i; los siguientes se desplazan a la izquierda.La longitud disminuye en 1; el antiguo elemento i+1 pasa a i.
FOR EACH x IN LVisita cada valor del primero al último.Útil si el algoritmo necesita los valores, pero no los índices.

El procedimiento cuenta los valores estrictamente mayores que un límite y devuelve el total. Visitar cada elemento no modifica la lista:

PROCEDURE countAbove(values, limit)
{
    count ← 0
    FOR EACH value IN values
    {
        IF (value > limit)
        {
            count ← count + 1
        }
    }
    RETURN(count)
}

answer ← countAbove([8, 5, 9, 6], 6)
DISPLAY(answer)

La llamada devuelve 2: 8 y 9 son mayores que 6; 5 y 6 no lo son. En cada pasada, anota el valor actual y el recuento después de la prueba. La comparación es estricta: cambiar > por >= también incluiría 6.

Al seguir una pregunta, registra la lista antes y después de cada cambio, su longitud actual y la condición evaluada. Los índices menores que 1 o mayores que LENGTH(L) producen un error y terminan el programa según la semántica de la hoja. Al recorrer y eliminar elementos, ten en cuenta el desplazamiento: después de borrar el elemento actual, el siguiente ocupa el mismo índice; incrementar un índice manual puede saltarlo.

14 · versiones y alcance

Vigencia y límites

La hoja de referencia y el marco del curso pueden revisarse entre años escolares y exámenes. Esta página se basa en la hoja de 2026; los estudiantes deben confirmar qué material corresponde a su evaluación.

El pseudocódigo AP CSP es una notación compartida para la enseñanza y los exámenes, no un lenguaje de propósito general ni una API. Esta página no afirma que Potoo IDE lo ejecute ni sustituye el documento oficial.
