01 · panorama

Qué es C0

C0 se diseñó para enseñar programación imperativa y estructuras de datos con una sintaxis familiar para quienes conocen C, pero con menos características y reglas más controladas. Se utiliza en cursos introductorios de Carnegie Mellon University, incluidos materiales de la asignatura 15-122.

El objetivo didáctico es hacer explícitos los tipos, el flujo de control, la memoria y las condiciones que debe respetar una función. El curso describe C0 como un subconjunto seguro de C, con recolección automática de memoria, enteros de intervalo fijo y contratos. El lenguaje define su comportamiento para que el alumnado no dependa de casos indefinidos de C. No pretende aceptar todos los programas de C: un archivo puede depender de características que no existen en C0.

Estado en Potoo IDE: C0 está en evaluación. El entorno y las herramientas de compilación de Carnegie Mellon son las referencias para ejecutar los ejemplos de esta página.

02 · contexto

Origen y objetivos didácticos

C0 se desarrolló para apoyar la enseñanza de programación y el razonamiento sobre la memoria. Su sintaxis se parece a la de un lenguaje de la familia C, mientras que su diseño restringe construcciones que dificultarían analizar el comportamiento de un programa para principiantes.

La referencia oficial organiza el lenguaje en torno a funciones, tipos, instrucciones y contratos. Los cursos utilizan estos recursos para desarrollar soluciones correctas y explicar por qué funciona una función, en vez de limitarse a obtener una salida para un caso de prueba.

  • Programación imperativa: variables, asignaciones, llamadas, condiciones y bucles.
  • Abstracción: funciones y estructuras nombran operaciones y datos relacionados.
  • Razonamiento sobre corrección: precondiciones, poscondiciones e invariantes expresan lo que debe cumplirse.

03 · datos y tipos

Tipos, valores y colecciones

C0 define los valores y las operaciones con precisión para que los programas no dependan de los casos indefinidos de C. Las reglas de int, texto, arreglos y estructuras pertenecen al lenguaje; no deben deducirse de un compilador C común.

Tipo o formaQué representaRegla para recordar
intPalabra entera de 32 bits en complemento a dos.La aritmética es módulo 232; los valores vuelven del máximo al mínimo representable.
boolUno de los valores true y false.Las condiciones y los contratos deben producir un booleano; && y || tienen cortocircuito.
charCarácter ASCII, no Unicode.Las comparaciones siguen el código ASCII; los literales usan comillas simples.
stringTexto constante formado por caracteres ASCII.\0 no puede aparecer en un literal; compara con funciones de biblioteca, no con ==.
t[]Referencia a un arreglo asignado de valores del tipo t.Se crea con alloc_array(t, n); los índices válidos van de 0 a n-1.
t*Puntero a un valor t en memoria; puede ser NULL.alloc(t) crea la posición; comprueba p != NULL antes de *p para evitar un fallo por puntero nulo.
struct sRegistro con nombre y campos de distintos tipos.Se asigna en memoria y se usa mediante un puntero, como p->field; no se copia por valor como un int.
voidTipo de retorno para una función sin resultado.Se usa solo en funciones llamadas como instrucciones.

Los arreglos son referencias pequeñas a un área de longitud fija. Un acceso fuera de los límites —índice negativo o mayor o igual que la longitud— provoca una infracción de límites y termina el programa. El recolector automático de memoria gestiona los arreglos y estructuras que dejan de ser alcanzables; el programa no llama a free. Esto evita la liberación manual, pero no vuelve seguro cualquier acceso: los límites, los valores nulos y las relaciones entre campos todavía requieren razonamiento.

El entero es modular, no un número de precisión ilimitada: por ejemplo, incrementar el mayor int representable hace que el resultado vuelva al menor valor. La división entera trunca hacia cero; dividir entre cero y el caso especial -2^31 / -1 producen un error aritmético. Si el ejercicio exige un intervalo menor, decláralo en el contrato y compruébalo antes de calcular.

04 · estructura

Funciones, declaraciones y bloques

Un programa se organiza en funciones. La firma declara el tipo del resultado, el nombre de la función y los tipos de los parámetros; el cuerpo se delimita con llaves. Las declaraciones locales introducen valores usados en un bloque, y return termina una función produciendo el resultado esperado.

int square(int value) {
    return value * value;
}

int main() {
    int result = square(6);
    return 0;
}

El ejemplo muestra una función pura pequeña y una función de entrada convencional. La biblioteca y el contrato requerido para main pueden depender del entorno de compilación del curso. Los comentarios deben explicar el propósito o una decisión relevante, no sustituir una descripción precisa de parámetros y resultados.

05 · flujo de control

Decisiones, bucles y llamadas

C0 ofrece las instrucciones habituales de un modelo imperativo: secuencia, selección, repetición, llamadas a funciones y retornos. Las condiciones son expresiones booleanas. Un bucle debe avanzar hacia su condición de salida; razonar informalmente sobre ese avance ayuda a evitar programas que no terminan.

ConstrucciónFunción
if / elseElige un bloque a partir de una condición.
whileRepite mientras la condición siga siendo verdadera.
forAgrupa inicialización, condición y actualización en un bucle contado.
returnDevuelve el valor declarado por la firma de la función.

Los arreglos, las estructuras y los punteros permiten representar colecciones y relaciones entre datos. Cada acceso a un arreglo debe permanecer dentro de sus límites válidos; salir de ellos es una infracción de seguridad. Utiliza contratos e invariantes para justificar índices y relaciones entre datos, sin presuponer el comportamiento de otra implementación de C.

06 · corrección

Contratos, invariantes y seguridad

Los contratos registran las condiciones para llamar a una función y lo que garantiza al terminar. Una precondición expresa un requisito de entrada; una poscondición describe el resultado. Un invariante de bucle resume una propiedad que debe seguir siendo cierta en cada repetición.

  • Precondición: indica límites y relaciones que deben cumplir los argumentos.
  • Poscondición: relaciona el valor devuelto con el problema resuelto por la función.
  • Invariante: explica el significado del estado mantenido durante un algoritmo iterativo.
AnotaciónQué especificaComprobación dinámica
//@requiresCondición que deben cumplir los argumentos.Antes del cuerpo de la función.
//@ensuresPropiedad del resultado; puede usar \result.Antes de que la función retorne.
//@loop_invariantPropiedad que debe cumplirse durante el bucle.En cada iteración, antes del test de salida.

La referencia escribe precondiciones y poscondiciones en comentarios especiales, como //@requires expresión; y //@ensures expresión;. En una poscondición, \result representa el valor devuelto. Los invariantes de bucle utilizan //@loop_invariant expresión; y deben ser expresiones lógicas. Cuando se habilita la comprobación dinámica, las herramientas evalúan estos contratos en los puntos definidos por la referencia; quien escribe el programa sigue siendo responsable de los contratos correctos y del razonamiento sobre límites.

int maximum(int x, int y)
//@ensures \result >= x && \result >= y;
{
    if (x > y) {
        return x;
    } else {
        return y;
    }
}

07 · ejemplo guiado

Planificar una función de búsqueda

Considera una función que busca un entero en un arreglo. Antes de implementarla, define qué significa «encontrado»: devolver un índice válido si aparece el valor y comunicar su ausencia en caso contrario. El tipo y el valor para representar «no encontrado» deben seguir la convención del ejercicio.

  1. Declara los argumentos del arreglo, su tamaño y el valor buscado.
  2. Decide si se permite tamaño cero y qué condición debe cumplir el arreglo.
  3. Recorre los índices válidos en orden y compara cada elemento.
  4. Devuelve el índice en cuanto encuentres una coincidencia.
  5. Tras el bucle, devuelve el marcador de ausencia documentado.

Una poscondición puede relacionar el índice devuelto con el elemento coincidente. Si el resultado indica ausencia, debe expresar que ningún elemento del intervalo cumple la búsqueda. Así, la especificación también cubre arreglos vacíos y valores repetidos.

08 · estudio y depuración

Cómo estudiar y depurar C0

Compila fragmentos pequeños mientras aprendes. Para cada función, anota su firma, los casos de entrada y el significado esperado del resultado. Después sigue la ejecución con una tabla de variables; en algoritmos sobre colecciones, incluye el índice y el intervalo ya procesado.

  • Prueba valores límite: cero, tamaño mínimo, primer y último índice.
  • Ejercita las ramas verdadera y falsa de cada condición.
  • Incluye arreglos vacíos, de un elemento y con valores repetidos cuando el contrato lo permita.
  • Lee los mensajes del verificador o compilador junto con la precondición y el invariante pertinentes.

Un programa que compila aún puede resolver el problema equivocado. Compara la salida con un cálculo independiente y prueba casos que recorran todas las ramas.

09 · recorrido guiado

Arreglos, contratos y seguridad de memoria

Una función que recorre un arreglo debe relacionar tres hechos: la longitud guardada con la referencia, el índice actual y cuántos elementos se procesaron. Este ejemplo suma un prefijo de longitud n:

int sum_prefix(int[] values, int n)
//@requires 0 <= n && n <= \length(values);
{
    int i = 0;
    int total = 0;
    while (i < n)
    //@loop_invariant 0 <= i && i <= n;
    {
        total = total + values[i];
        i = i + 1;
    }
    return total;
}

Para values = [4, 2, 5] y n = 3, los pares (i, total) tras cada pasada son (1, 4), (2, 6) y (3, 11). Si n vale cero, el cuerpo no accede al arreglo y la función devuelve cero. La precondición impide que n supere la longitud; la condición i < n mantiene cada índice dentro del prefijo. El invariante escrito protege el límite del índice, pero no afirma por sí mismo que total sea la suma del prefijo; esa relación debe incluirse en la explicación de corrección.

OperaciónGarantía que se debe establecerFallo observable
alloc_array(t, n)n >= 0; los accesos usan 0 <= i < n.Un índice fuera del arreglo termina el programa.
alloc(t)Inicializa los campos antes de depender de ellos; un puntero puede ser NULL.Desreferenciar NULL termina el programa.
p->fieldp != NULL y el campo pertenece a la estructura declarada.El acceso mediante un puntero nulo termina con una excepción de ejecución.
//@requiresPrecondición verdadera antes del cuerpo, como un límite del arreglo.Con la comprobación dinámica habilitada, una llamada incorrecta falla antes del cuerpo.
//@ensures y //@loop_invariantLa poscondición describe el retorno; el invariante describe el estado en el punto del bucle.Con la comprobación dinámica habilitada, una propiedad falsa se detecta en los puntos definidos por la referencia.
assert(e);Condición interna que debe ser verdadera en este punto.La instrucción siempre se ejecuta; si e es falso, se aborta la ejecución.
error(s);Mensaje para rechazar una entrada inválida conocida.Muestra el mensaje y termina el programa.

Los contratos de función son comentarios especiales junto a la firma. //@requires especifica lo que debe garantizar quien llama; //@ensures puede usar \result para referirse al retorno. \length(A) solo se permite en contratos. El invariante de un bucle se comprueba en cada iteración inmediatamente antes de probar la condición de salida, cuando está habilitada la comprobación dinámica. Una compilación común puede no comprobar las anotaciones: usa las opciones de las herramientas del curso y lee los mensajes de error. La instrucción ejecutable assert(e); siempre se evalúa.

Un puntero necesita una justificación adicional de que el objeto existe. En una lista enlazada, comprueba NULL antes de cada lectura de campo. Las estructuras son valores grandes asignados en memoria y normalmente se pasan como punteros; al asignarlas, sus campos reciben los valores predeterminados de sus tipos. El recolector automático evita llamar a free, pero no corrige un campo no inicializado para la tarea, una referencia nula ni una estructura que incumple el invariante supuesto por el algoritmo.

struct node {
    int value;
    struct node* next;
};

struct node* first = alloc(struct node);
first->value = 7;
first->next = NULL;
if (first->next != NULL) {
    int next_value = first->next->value;
}

Al depurar, prueba por separado un arreglo vacío, un elemento, el último índice válido y el primer índice inválido. Para punteros, prueba tanto el caso nulo como un objeto asignado; para aritmética, usa valores cercanos a los extremos de 32 bits. El compilador puede detectar incompatibilidades de tipos, mientras que los contratos y las tablas de ejecución ayudan a localizar precondiciones, límites e invariantes incumplidos.

Alcance de esta referencia
